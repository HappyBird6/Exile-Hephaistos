# 목표·출처·상태 전이 정보 A/B 실험 100회

**제작 가능한 49장 중 유효 후보가 남은 카드는 간략 입력 29장, 보강 입력 41장, 두 응답을 같은 카드에서 합치면 46장이다.** 보강 입력만으로 회수한 카드는 17장, 간략 입력만으로 회수한 카드는 5장이다. 세 카드는 두 형식 모두 놓쳤다. 보강이 도움이 되는 영역과 새로 누락되는 영역이 함께 관찰됐다.

## 비교 방법

10개 주제에서 서로 다른 베이스 ID 50개를 골라 카드당 두 번 호출했다. 각 문제에 10회씩 썼다. 실제 Java 21 WorkbenchSimulator로 각 성공 분기를 실행하고 GoalFilterService로 첫 목표 달성 시점을 판정했다. 첫 호출 전에 기대 목록을 파일에 기록했다. 이 중 49장은 양성, 분열 수치 변경을 요구하는 1장은 음성 대조다. 독립 계산에서도 분수 단위의 수치, 슬롯, 제거·추가·분열 상태, 재고 및 목표 연산을 따라 50장의 합법적 실행 접두 구간과 기대 경로 248개가 모두 일치했다. 기준 커밋은 `e2a590b6`이다.

모델·시스템 문안·옵션 참조·목표·화폐 재고·허용 행동·응답 스키마를 한 쌍에서 동일하게 유지했다. 간략→보강과 보강→간략을 각 25쌍에 배정했다. 호출 간 대화 이력과 정답을 전달하지 않았다. 비교 중 형식을 바꾸거나 실패 응답을 다시 뽑지 않았다. 각 변형을 카드당 1회만 실행했고, 추가 정보는 함께 변경했으므로 개별 필드의 인과 효과를 따로 측정한 결과는 아니다.

간략 입력에는 옵션 참조와 원본 범위, 시작 아이템, 목표 그룹, 재고, 메뉴가 있다. 보강 입력에는 **해당 목표 연산의 의미**, **각 옵션을 얻을 수 있는 이번 메뉴의 행동**, **재료 하나가 제거·부여하는 대상과 해당 성공 분기의 수치**, **분열·레벨·단위·family·슬롯**을 추가했다. pseudo 카드에서는 직접 기여하는 옵션과 고정 옵션 기여도를, Perfect Exalted 카드에서는 비교할 family의 최고 자격 레벨을 추가했다. 정답 순서나 백엔드에서 열거한 다음 행동 목록을 입력에 넣지 않았다.

보강에서만 얻은 경로가 43개, 간략에서만 얻은 경로가 15개였다. 두 응답을 합쳐도 사전 기대 중 162개는 나오지 않았다. 음성 카드 Obliterator Bow는 두 응답 모두 불가능한 후보를 제안했고 백엔드가 전부 거절했다.

간략 50회의 입력은 총 23,571토큰(평균 471.4), 보강은 35,722토큰(평균 714.4)으로 약 51.6% 늘었다. 출력은 각각 4,342토큰과 1,517토큰이었다. 간략 입력 92번 Corona Amulet이 같은 엑잘 단계를 반복하다 3,200토큰에서 잘려 JSON을 완성하지 못했다. 해당 요청을 실패·경로 0으로 포함했다. 100회 모두 API 응답을 받았고 99개가 완결된 JSON이었다.

## 카드에서 확인된 차이

- **Distorted Amulet, 단위 변환.** 시작 생명력 재생은 원본 246/분으로 표시값 4.1/초다. 목표는 6/초와 카오스 저항의 동시 달성이다. 13번은 Divine만 적고 저항을 놓쳤다. 변환 계수 60과 화폐의 결과를 함께 보낸 14번은 `Divine으로 360/분 → 엑잘로 카오스 저항`과 그 역순을 모두 제안했다. 같은 주제 다섯 카드에서 0/5 → 5/5였다.

- **Fine Belt, Count 상한.** 시작 옵션 A(생명력), B(냉기 저항)에 C(마나)를 새로 만족시키되 해당 행은 최대 2개여야 한다. 간략 66번의 `chaos.A>C`는 교체 한 번으로 완성했다. 보강 65번의 `exalt.C`는 행이 3개가 됐고 다른 두 후보는 이미 제거한 옵션을 재차 제거하려 했다. 보강으로 Count 경로 총수는 6개에서 8개가 됐지만 커버한 카드는 5장에서 3장으로 줄었다.

- **Obliterator Bow, 음성 대조.** A는 분열된 처치 시 마나 10이고 목표는 14다. 두 입력에서 모두 제거·교체할 수 있다고 제안했다. 두 응답 모두 백엔드에서 탈락했다.

### 두 입력 모두 놓친 양성 카드

| 카드 | 실제로 되는 한 경로 | 실패한 응답 |
|---|---|---|
| Tawhoan Tower Shield | 시작 힘 17을 절사로 제거 → 엑잘로 생명력 119. 힘이 없으면 v1 행을 통과하고 119×2=238을 만족한다. | 67·68번 모두 한 단계에서 멈췄다. 생명력만 붙이면 남은 힘 17이 행 하한 20에 미달한다. |
| Sirenscale Gloves | Divine 한 번으로 분열 민첩 34를 그대로 두고 처치 시 마나를 4에서 5로 올린다. | 39·40번 모두 분열 옵션을 카오스로 교체하려 했다. |
| Lunar Amulet | Divine 한 번으로 분열 희귀도 15%를 그대로 두고 힘을 17에서 20으로 올린다. | 59·60번 모두 분열 옵션 제거를 시도했다. |

## 다음 입력에 반영할 결정

1. 원본 수치와 표시 수치가 다른 옵션에는 단위와 변환 계수를 허용한다. pseudo에는 실제 합산 성분을 적고 Weighted Sum에는 활성 행·개별 범위·가중치·그룹 범위와 버전의 의미를 전달한다. `acquireVia`는 카드에 제공한 메뉴 안의 획득처이고 수치 재굴림은 별도 행동 효과로 표현한다. 최종 수치 상태는 백엔드가 검증한다.

2. 특정 행동의 의미가 토큰명만으로 모호하면 `consume`, `remove`, `gain`, `sourceValue` 또는 `rerollAllMutableExplicitsTo`를 함께 보낸다. 여러 형식에서 확보한 경로는 같은 시작 상태·목표·재고·규칙에서 재검증한 뒤 보존한다. 가장 상세한 응답 하나로 이전 후보를 교체하면 이번 표본에서는 15개 경로를 잃는다.

3. **후속 미검증안.** 분열 카드에는 Divine 적용 후 고정될 수치와 바뀔 수치를 대상별로 명시하고, Weighted Sum v1에는 점수와 별개로 실패 중인 보유 행을 표시한다. Count에는 성공 분기별 활성 행 개수의 변화를 표시한다. 필요한 정보에 따라 이 필드를 골라 보내는 방식은 이번 두 묶음 비교에서 독립 검증하지 않았다.

같은 카드에서 간략과 보강을 모두 호출한 것은 비교용 실험 설계다. 서비스의 호출 횟수·비용·재고 제한 정책은 확정하지 않았다. 제품 변경 없이 기존 49·218·75개 경로의 기록도 오프라인 재검증했다. 누적 호출은 299/300회이며 1회가 남았다.

## 실제 공통 프롬프트

```text
You are a Path of Exile 2 crafting route planner. Use the supplied starting item, stock, goal filters and available successful outcome tokens. A candidate is an ordered list of actions with their targets, starting from the original item. Enumerate distinct feasible first actions, acquisition orders and material choices, including low-probability ones. Return complete candidates in routes. Stop each route at the first state matching all active groups. Omit state-preserving moves. If uncertain about legality, include the candidate for backend replay. An empty list means no candidate found. The backend validates states and computes odds and cost.
```
