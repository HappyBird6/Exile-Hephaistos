# 제작지원 LLM 통신 설계 기록

## 가능성 검토

완성 카드 한 장을 목표로, 시작 아이템에서 어떤 순서로 화폐를 쓰고 옵션을 확보할지 여러 레시피 후보를 받는다. **비용이 높거나 검증에서 탈락할 후보가 섞이는 것은 허용한다. 우선 줄일 오류는 실제로 가능한 레시피를 후보에서 빠뜨리는 것이다.** 현재는 설계 논의 단계이며 전송 JSON과 응답 형식은 미정이다.

현재 규칙안과 카드별 기대 응답은 [완성 카드별 제작 레시피 후보 생성 규칙](recipe-candidate-rules.md)에 모았다. 아래 A·B·C 표는 초기 논의 기록이다. 실제 후보를 작성할 때는 규칙안의 시나리오 1에 정리한 더미용 엑잘의 후속 조건과 마무리 엑잘의 허용 조건을 적용한다.

[전송·응답 JSON 초안](card-recipe-json-draft.md)에는 태양의 목걸이 세 카드의 요청과 결과별 제작 분기를 기록했다. 생명력 티어별 획득처를 비교하고, 단일 기폭제에서 생명력·힘이 함께 Weighted Sum을 충족하는 조합을 전수 대조했다. 세 번째 사례에 그대로 전송할 프롬프트와 기대 응답이 있다.

## 입력을 줄일 때 남길 정보

행동 순서만 요청하는 간소한 형식의 실제 모델 실험은 [시나리오별 기대·실제 응답 비교](recipe-prompt-experiment-20261123.md)에 기록했다. 최종 문안과 행동·대상 사전이 개선한 사례, 여전히 누락된 경로를 함께 확인할 수 있다.

[후속 50회 실험과 최종 P6 문안](recipe-prompt-followup.md)에서는 행동을 직접 나열하는 방식과 목표 순서를 받은 뒤 출처를 펼치는 방식을 비교했다. 분열 목걸이의 누락 개선, 마법봉의 남은 순서 편향, 도달 불가 사례의 오류를 실제 응답과 함께 기록했다.

| 판단할 내용 | 카드별로 전달할 정보 제안 |
|---|---|
| 이미 확보한 옵션과 보존할 옵션은 무엇인가? | 시작 베이스·레벨·희귀도, 현재 옵션과 분열 여부, 해당 카드에 영향을 주는 품질·소켓 등 상태 |
| 어떤 조합이면 성공인가? | 원래 목표 그룹과 활성 행의 수치·범위·가중치, 카드에서 함께 성립하는 티어 조합. 대표 아이템의 예시 수치와 사용자가 요구한 수치를 구분한다. |
| 어떤 화폐를 고려해야 하는가? | 허용 티어별 **모든 획득처**와 구체적인 화폐 ID. 동일한 출처 목록은 한 번 전송하고 여러 티어에서 참조할 수 있다. `base`는 일반 옵션 풀을 뜻하며, 그 풀에서 뽑는 화폐는 현재 상태에 따라 달라진다. |
| 무엇을 먼저 확보할 만한가? | 확인된 경우 목표 티어들의 추첨 가중치 합과 해당 풀의 총가중치 등 대략적인 희소성. 확률이 미확정인 출처는 ‘미확정’으로 남긴다. |

처음부터 전체 카탈로그나 화폐 사용 후 매번 달라지는 확률 분모를 전송할 필요는 없다. 먼저 입력을 줄일 대상은 중복 정의와 정밀 계산용 데이터다. 낮은 가중치는 해당 옵션을 먼저 노려 볼 근거이고, 후보에서 제거할 근거가 되지 않는다. 제작 슬롯 확장이나 제거 대상 보호처럼 순서의 성립 여부를 바꾸는 정보가 부족하면 전제 조건을 붙여 후보를 남긴다. 백엔드는 반환된 후보의 전이 가능 여부와 목표 달성을 재검증하고 정확한 확률·비용을 계산한다. 후보 목록이 비어 있다는 사실만으로 제작 불가를 확정하지 않는다.

## 기대하는 레시피의 단위

후보 하나에는 **옵션 획득 순서, 단계별 화폐, 보존할 옵션, 다음 행동이 달라지는 조건**이 드러나야 한다. 예를 들어 ‘C를 얻을 때까지 1옵션 카오스 반복’은 한 단계로 표현할 수 있다. C가 뜨면 반복을 끝낸다는 의미이며 한 번의 사용으로 C가 확정된다는 뜻은 아니다. 두 전략 중 사용자가 고르는 지점과 화폐의 무작위 결과로 다음 단계가 갈리는 지점은 구별한다.

### A·B·C로 비교하는 두 후보

희귀 1옵션에서 시작하고, 목표 A·B·C는 계열이 충돌하지 않는 접두라고 가정한다. A는 교체형 에센스 전용, B는 에센스 또는 일반 풀, C는 일반 풀에서만 나오는 낮은 가중치의 옵션이다. 이 예시의 제작 옵션 한도는 하나이므로 A에 에센스를 쓰고 B는 일반 풀에서 얻는다. 다른 베이스에서 증강물로 제작 한도를 늘릴 수 있다면 그 조건으로 B의 에센스 경로도 검토한다.

| 후보 | 화폐 사용 순서와 분기 |
|---|---|
| C → A → B | 시작 단계의 1옵션 카오스 반복으로 C를 확보한다. 엑잘로 제거 가능한 접미가 붙으면 접미 제거 징조와 A 에센스를 함께 써서 C를 보존한다. 남은 접두에 엑잘로 B를 노린다. 첫 엑잘에서 B가 먼저 붙으면 다음 후보의 마무리 단계로 합류한다. |
| C → B → A | C 확보 후 엑잘로 B를 먼저 노린다. C와 B가 남아 있고 A가 들어갈 접두 자리와 제거할 접미가 있으면 징조와 에센스로 마무리한다. 마지막 접두가 다른 옵션으로 찼다면 이 상태에서 엑잘을 계속 쓰는 단계는 종료하고 복구 가능성을 별도로 검토한다. |

두 후보는 A에 에센스 비용을 지불하는 시점이 다르다. 접미 제거 징조의 적용 가능 여부, 남은 접두 자리, 실제 제거 대상과 재시도 비용은 백엔드가 각 상태에서 확인한다.

### 실제 카드로 남겨 둘 비교 사례

아이템 레벨 82 희귀 태양의 목걸이에서 목표는 `AND(최대 생명력 = 90, 일반 방어도·회피·에너지 보호막 증가 = 25%)`다. 조회한 카드에서 T3 `Rotund`의 출처는 일반 풀, `GREATER_ESSENCE_BODY`, `Preserved_Collarbone`, `Ancient_Collarbone`, `Altered_Collarbone`이고, T1 복합 방어 접두의 출처는 `PERFECT_ESSENCE_ENHANCEMENT`다. 시작 아이템에 생명력 +90과 힘 +6만 명시 옵션으로 붙어 있다면, 접미 제거 징조를 쓰는 후보는 힘을 제거하고 생명력을 보존한다. 에센스 단독 사용 후보는 생명력을 잃을 수 있어 복구 분기가 생긴다. 두 후보 모두 방어 수치가 25%인지 확인해야 한다. 수치를 다시 굴리면 생명력도 다시 확인한다.

다음 실험부터는 이 표 아래에 날짜별로 **카드와 시작 상태 → 바꾼 입력·프롬프트 → 기대 후보와 실제 응답 → 백엔드 검증 결과 → 다음 변경**을 덧붙인다. 가능하다고 확인한 후보가 빠졌는지와 반환됐지만 탈락한 후보를 따로 기록하고, 입력을 줄인 실험은 전후 입력량도 함께 적는다.
