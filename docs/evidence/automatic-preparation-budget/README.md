# v4 준비 규칙의 최대 예산 관찰

`AutomaticPreparationBudgetTest.java`는 최종 제품 테스트를 대체하지 않는 수동 진단 프로브다. 기존 `IndependentPlannerReviewTest`의 완료 단언은 그대로 남겼다. 20,000에서 멈춘 결과를 성공으로 바꾸지 않으며, 상한이나 단언을 완화하지 않는다.

격리된 소스 복사본의 `backend/src/test/java/com/poe2craft/bootstrap/`에 이 파일을 복사한 뒤 기존 Gradle `test --tests com.poe2craft.bootstrap.AutomaticPreparationBudgetTest`로 실행했다. 실제 정책·카탈로그·확률 모델을 사용한다. `AutomaticSearchService.RESUME`와 동일한 증가식으로 64/128/20,000/5,000에서 128/256/40,000/10,000, 이어 128/256/50,000/10,000까지 진행했다. 제품 서비스나 저장 파일을 호출하지 않는다.

| 시나리오 | 최대 예산에서 관찰한 결과 |
| --- | --- |
| 06 | 14,777 단계, 재개 2회. 방법 2개, 구체 상태 219개, 목표 상태 218개. 레코드 50,026/50,000, `RETAINED_RECORDS`, `canResume=false`, 미완료 |
| 07 | 재개 2회 뒤 500,000 단계까지 관찰. 방법 1개, 구체 상태 198개, 목표 상태 197개. 레코드 33,300/50,000, blockers 없음, `canResume=true`, 미완료 |

07의 최대 예산에서는 내부 기록 일부가 정리되어 40,017에서 33,300으로 줄었다. 따라서 v3의 50,000 상한 중단 결과를 v4에 그대로 적용할 수 없다. 500,000 단계의 관찰 가드에서 끝났으므로 최종적으로 완료 가능한지, 이후 상한에 도달하는지는 이 실험으로 확정하지 않는다.

프로브는 07이 관찰 가드 전에 완료 또는 실제 재개 불가 상한에 도달해야 한다는 단언에서 실패했다. 이 실패를 통과로 바꾸지 않았다. 장시간 진단을 기본 테스트에 반복 실행하지 않도록 문서의 재현 자료로 보관한다. 원본 완료 회귀 테스트 05/06/07은 여전히 기본 테스트에 남아 있다.

원시 보고서는 작업 폴더의 `evidence/grade-remaining-r1-tests/TEST-com.poe2craft.bootstrap.AutomaticPreparationBudgetTest.xml`이다. 이 검사에서 앞서 나온 저장 호환성 실패는 후속 수정 및 별도 재검사로 해결했으며, 최대 예산 수치는 품질 목표가 없는 동일한 v4 준비 규칙에서 얻었다.
