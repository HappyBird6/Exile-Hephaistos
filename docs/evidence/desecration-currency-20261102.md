# WB-052 — 수동 작업대 뼈 화폐 적용

기준: `24a4d5c6cd80392b8ee263af94d9bae08e67d0fb`, 작업 브랜치 `codex/manual-workbench-20261102`.

## 구현한 동작

첫 Currency 탭에 아래 9종을 추가했다. 실제 서버 상태 전이를 수행하고 일반 film에 저장한다. 적용은 **관측한 결과를 입력하는 조건부 수동 전이**다. 접두/접미 또는 제거 대상의 무작위 확률을 생성하는 시뮬레이터가 아니다. 화면에도 이를 명시한다. 후보 3개를 직접 관측·입력·선택하는 기존 드러내기와 화폐 사용을 분리한다.

| 계열 | 화폐 | 적용 대상 | 등급 제약 |
|---|---|---|---|
| 갈비뼈 | Gnawed_Rib / Preserved_Rib / Ancient_Rib | 희귀 방어구, 방패·버클러·집중구 포함 | 갉힌: 아이템 레벨 ≤64, 고대: 드러낸 옵션 레벨 ≥40 |
| 턱뼈 | Gnawed_Jawbone / Preserved_Jawbone / Ancient_Jawbone | 희귀 무기·화살통 | 동일 |
| 빗장뼈 | Gnawed_Collarbone / Preserved_Collarbone / Ancient_Collarbone | 희귀 목걸이·반지·허리띠 | 동일 |

- 신규 `/api/v1/crafting/workbench/abyss/desecrate`는 ruleset 헤더를 요구한다. 본문은 `state`, `currency`, 관측 `side`, 가득 찼을 때의 `removedSlotId`, `activeOmens`다.
- 미공개 훼손도 실제 접두/접미 슬롯 하나를 차지한다. 이미 훼손된 아이템에는 뼈 화폐를 다시 적용하지 않는다. 관측 시나리오의 다중 슬롯과 기존 저장 기록은 삭제하지 않는다.
- 6옵션일 때만 관측한 제거 대상을 요구한다. 분열 옵션 제거, 포화된 반대쪽으로의 삽입, 일반/마법/고유, 특수 상태, 잘못된 장비 종류, 잘못된 레벨, 미해결 장착 증강을 원자적으로 거절한다.
- 모든 활성 징조는 이번 뼈 단독 경로에서 거절하고 보존한다. 징조를 소모했다고 표시하거나 효과를 몰래 무시하지 않는다.
- `minimumModifierLevel`은 훼손 슬롯의 선택적 필드다. 고대의 40 제한을 저장·복원·관측·선택 및 후속 슬롯 제작에 보존한다. 예전 3필드 common 슬롯/4필드 Abyss 슬롯 생성자는 유지하고 HTTP에서는 없는 새 값을 생략한다.
- film은 손실 없는 common 아이템 및 Abyss offer를 함께 보존한다. 관측과 선택 단계는 화폐 소비 횟수에 추가하지 않는다. 과거 단계에서 다시 진행하면 원본 film과 원문을 보존해 분기한다.
- 작업대에서는 별도 Abyss localStorage를 읽고 쓰지 않는다. 저장된 후보가 다른 film에 섞이지 않는다. 옛 별도 시나리오 저장 파일은 보존하며 전략 화면의 기존 저장 방식은 유지한다.
- 다른 항목을 선택하거나 페이지에서 나간 후 도착한 이전 Abyss 응답은 무시한다. 요청 실패는 기존 film과 아이템을 변경하지 않는다.
- 134종 카탈로그와 기존 하위 베이스 기록, 130종 신규 선택 목록은 변경하지 않았다. 새 화폐가 적용되는 것은 위 장비 클래스이며 주얼은 아래 제한을 따른다.

## 근거와 버전 경계

- [GGG 공식 0.3.0 패치: Rise of the Abyssals](https://www.pathofexile.com/forum/view-thread/3826682/filter-account-type/staff): 뼈로 숨은 속성을 부여하고 Well of Souls에서 3개 중 선택하는 절차.
- [게임 데이터 설명·등급·분류](https://poe2db.tw/us/Desecrated_Modifiers): 원문 키워드 설명에서 포화 시 제거, 기존 훼손 재사용 불가, 9종의 대상/레벨 제한 확인. 페이지 하단 커뮤니티의 가중치 추정은 사용하지 않았다.
- 기존 카탈로그의 itemClass, 옵션 ID·수치 범위·충돌군·requiredItemLevel 및 분열 보호를 사용한다. 최신 웹페이지의 새 옵션을 현재 봉인된 카탈로그에 추측해서 합치지 않았다.
- 실제 6언어 명칭/출처와 자산 다운로드 결과: `desecration-assets-20261102.json`. 원본 CDN 다운로드는 9건 모두 HTTP 403. 저장된 이미지 없음. 대신 현지화된 이름을 텍스트 타일로 표시한다. 임의 게임 아이콘을 만들지 않았다.

## 완료되지 않은 지원

1. **무작위 접두/접미·제거·후보 생성**: 확인한 설명은 무작위라고만 하며 확률 분포가 없다. 균등확률 또는 기존 일반 화폐 가중치로 대체하지 않았다. 이번 적용은 관측 결과의 실제 상태 반영이다.
2. **Preserved Cranium**: 현재 주얼 카탈로그/작업대의 훼손 미지원 경계 및 특수 Crafted 추가 슬롯과 기존 overflow 규칙을 별도 확장해야 한다. 현재 주얼 카탈로그에는 훼손 전용 옵션이 등록되지 않았다. 단순히 방어구 슬롯 모델을 적용하면 틀린 주얼 상태를 허용한다. 이 부분은 미구현이며 별도 승인 필요가 아니라 추가 모델·데이터 검증이 필요한 잔여 작업이다.
3. **Preserved Vertebrae**: 경로석 베이스·옵션이 현재 134종 장비 카탈로그에 없다.
4. **Altered Collarbone / Lich 보장·Putrefaction·Necromancy·Echoes 화폐 소비**: 전용 풀, 후보 생성/재시도 분포, 소비·타락 전이의 검증 모델이 없다. 이번에는 뼈 단독 결과만 지원하며 기존 Essence of the Abyss 및 슬롯 인지 일반 화폐는 중복 구현하지 않았다.
5. **Mark of the Abyssal Lord 보유 아이템**: 원문은 표식 교체와 더 높은 등급을 지정한다. 현재 카탈로그에 표식이 있지만 고등급 보장 해석은 별도 규칙이 필요하다. 일반 뼈처럼 표식을 남기지 않도록 명시적으로 거절한다.
6. 고대 제한이 있는 슬롯을 자동 제작 그래프로 전환하는 기능은 자동 프로토콜에 해당 필드가 없어 차단한다. 수동 제작·film 복원은 지원한다.
7. 자동 브라우저 검증은 사용자 지시로 수행하지 않았다. 운영 재시작·배포·push도 수행하지 않았다.

## 직접 확인 순서

1. 희귀 목걸이를 준비하고 첫 Currency 탭에서 보존된 빗장뼈 선택 → 관측한 접두/접미 선택 → 중앙 아이템에 적용.
2. 미공개 슬롯 1개, 원래 옵션·분열·품질·소켓 유지, 제작 기록 1단계 추가 확인.
3. 훼손 슬롯 선택 → 실제 후보 3개 입력 → 후보 선택. 기록을 앞뒤로 이동하고 페이지를 다시 열어 후보·선택 상태 확인.
4. 6옵션에서는 제거된 일반 옵션도 선택하고 적용. 분열 옵션은 제거 선택지에 없어야 하며 잘못된 반대쪽 결과는 실패해야 한다.
5. 갉힌 뼈를 레벨65 이상에 적용하거나 이미 훼손된 아이템에 재사용하면 원본과 기록이 그대로여야 한다.
6. 고대 뼈 적용 → 저장/복원 → 레벨40 미만 후보가 선택지에서 제외되고 API도 거절하는지 확인.
7. 적용 취소·다른 아이템 전환·과거 단계 분기 후 이전 기록과 원문이 유지되는지 확인.

검증 수치와 최종 커밋은 체크포인트/JSON 보고서에 기록한다. 이 문서는 9종 관측 적용을 완료된 전체 훼손 시스템으로 표시하지 않는다.

## 검증 기록

- 구현 체크포인트: `700787303d7d94913a75129e8947b49da94ad8fd`.
- 영향 백엔드: 73/73 통과. 117개 등록 상위 장비 × 3개 뼈 등급 × 2개 접두/접미 = 702개 적용 조합 포함. 통합 8/8 통과.
- 전체 백엔드 `check generateJooq bootJar --continue`: 987개 중 40개 실패. **24a4d5c 체크포인트의 40개와 실패 식별자·메시지가 모두 동일**, 새 실패·새 메시지 차이 없음. 전체 check를 성공으로 표시하지 않는다. spotlessCheck·generateJooq·bootJar 및 통합 검사는 통과.
- 전체 백엔드 14분18초. 기존 DeferredCalculationTest의 정확한 분수 계산이 가장 긴 구간이며 이전 기록도 해당 메서드에 약 7분을 사용한다. 성능 개선이나 테스트 생략은 이번 변경에 넣지 않았다.
- 프런트 기존 테스트의 Currency 22개 기대값은 새 9종을 포함하는 31개로 수정했고, Omen의 22개는 유지했다. 개별 화폐 출처 링크도 기존 계약에 맞췄다. 관련 25개 테스트 통과. 최종 전체 결과는 JSON 검증 기록에 확정한다.

- 복원된 옵션 순서가 서버의 `ItemState` 정렬 순서와 다를 때, 사용자가 선택한 제거 옵션의 ID를 서버 슬롯 순서로 매핑한다. 표시 순서를 원본에서 바꾸거나 다른 옵션을 제거하지 않는다. 비정렬 6옵션 회귀 테스트를 추가했다.
- 원본 아이콘이 없는 이름 타일은 기본 탭뿐 아니라 즐겨찾기/커서에서도 현재 언어의 이름을 사용한다.

- 최종 프런트 단일 워커 전수 검사: 128개 파일, **2,411/2,411 통과**, 296.01초. 제거 대상 정렬 회귀 테스트를 포함한다. lint, typecheck, format:check, build 모두 통과했고 기존 번들 크기 경고만 남았다.
- 최종 변경 파일 목록과 검사 수치는 `desecration-validation-20261102.json`에 기록했다. 검증 컨테이너는 정리했고 실제 사용자 데이터와 기존 컨테이너는 보존했다.
