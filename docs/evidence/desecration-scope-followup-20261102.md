# WB-052 잔여 범위 재분류 및 Necromancy 구현

기준 커밋: `4c68c0a559b8cb92e6fd14e87c4e8cbe209daba6`.
브랜치: `codex/manual-workbench-20261102`.
이 보고서는 전체 훼손 제작 완료 보고가 아니다. **관측 상태 전이 구현**, **추가 데이터/규칙 검증**, **남은 구현**, **현재 작업대 밖 범위**를 구별한다. 모델이 없다는 사실만으로 사용자 승인이 필요하다고 해석하지 않는다.

## 이번에 추가 완료한 동작

- 기존 장비용 뼈 9종에 Sinistral/Dextral Necromancy를 각각 연결했다. 기존 Omen 탭 항목을 활성화하며 중복 화폐를 만들지 않는다. 뼈 9종은 첫 Currency 탭에 유지한다.
- 활성 징조가 접두/접미를 결정한다. UI 선택값도 고정하고, API는 생략된 side를 확정하되 반대 side 입력은 거부한다. 두 징조 동시 사용 및 아직 지원하지 않는 조합은 거부한다.
- 기존 슬롯 수, 분열 보호, Ancient 최소 레벨, 기존 훼손 재적용 금지 등 검증은 그대로 적용한다. 성공한 응답의 상태 검증과 film 반영 이후에만 징조를 비활성화하고 소비 안내를 표시한다.
- film의 선택적 `manual.consumedOmens`에 소비를 저장한다. 기존 film에는 필드를 강제하지 않는다. 실패하면 기존 film과 활성 징조를 유지하고 재시도할 수 있다. 후보 관측/선택은 추가 징조 소비로 기록하지 않는다.
- 접두/접미 강제 효과는 확정 규칙이다. 별도 확률 가정이나 사용자 결정이 필요하지 않았다.

## 관측 모드와 시뮬레이터의 차이

현재 뼈 기능은 사용자가 실제 결과의 접두/접미 및 필요 시 제거 옵션을 입력하면 그 결과가 슬롯·보호 상태와 호환되는지 검사하고 새 상태를 저장한다. Necromancy는 side를 확정한다. 후보 3개도 관측 입력이며 서버가 생성하지 않는다. 따라서 클릭만으로 결과를 추첨하는 제작 시뮬레이터의 완성형이 아니고, 성공 확률/평균 비용/많은 반복의 통계값을 계산할 수 없다.

완전한 무작위 생성에는 side와 제거 대상의 법칙, 후보 풀·가중치, 3개 후보 추출 시 중복/충돌 처리, 특수 계열 등장 확률이 필요하다. 현재 카탈로그의 일반 제작 weight나 주얼의 `USER_APPROVED_UNIFORM_CANDIDATES_NOT_GAME_WEIGHTS`는 이 새로운 결합 분포의 근거가 아니다. “random”이라는 문구만으로 균등 분포를 사실로 만들지 않는다. 실제 분포가 계속 공개되지 않는다면 필요한 최소 제품 결정은 **검증 가능한 관측 모드를 유지할지, 실게임 확률과 구별한 명시적 근사 모드를 추가할지**다. 이 보고서에서는 새 근사 모드를 추가하지 않았다.

- 세부 카탈로그 감사 결과는 `desecration-scope-audit-20261102.json`에 있다. 기존 카탈로그·사용자 저장 내용은 변경하지 않았다.

## 검증 및 잔여 상태

Necromancy 확장은 별도 검사로 검증한다. 최종 수치는 `necromancy-validation-20261102.json`에 기록한다. 기존 4c68c0a의 전체 백엔드 987개/기존 실패40개 결과를 이번 수정 후 전수 실행으로 표현하지 않는다.

브라우저 검증은 사용자 요청대로 미실행. 운영 재시작·배포·push 미실행. 위 표의 미완료 구현은 도구 거부나 사용자 승인 대기로 표시하지 않는다. WB-052 전체는 여전히 미완료다.

최종 검사: 프런트 128파일/2,413개 전체 통과, lint/typecheck/format/build 통과(기존 번들 크기 경고). 백엔드 영향 74개와 통합 8개, spotlessCheck/bootJar 통과. 임시 검증 컨테이너 정리 확인. 자체 diff 리뷰에서 확정 side 검증, 실패 시 보존, 이전 film 호환성을 확인했다.
