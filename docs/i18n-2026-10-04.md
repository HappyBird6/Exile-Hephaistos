## Behavior and reversible decisions

- Menu order: English, Korean, Simplified Chinese (CN), Traditional Chinese (TW),
  Japanese, Spanish. Fresh storage defaults to Korean. Only
  `hephaistos.locale.v1` is added to local storage; films and other keys keep their
  original shape and game identifiers.
- Central service dictionaries use stable keys and English fallback. UI strings
  are service translations, not claims of official game terminology. Interpolation
  and `Intl.PluralRules` support counted crafting history; `Intl.NumberFormat`
  formats probabilities/counts, and a UTC `Intl.DateTimeFormat` helper is available.
- Names and material descriptions are presentation adapters joined on existing
  material IDs, action-to-material IDs, supported base slugs or verified base
  metadata. Original English catalog fields, modifier rolls, API requests, cache
  keys, serialized films, currency eligibility, weights and rules are unchanged.
- Search accepts the selected language, English, and canonical IDs. Material
  tooltips link to the actual language source; unverified descriptions explicitly
  retain English. Custom/pasted item names are preserved; translated base names
  require an explicit base identity rather than a display-name guess.
- Existing English UI behavior tests select English in test setup. The dedicated
  i18n suite checks Korean default resolution, six-language key/placeholder parity,
  interpolation/pluralization, ID joins, fallback, search, number/date formatting,
  menu order, saved-data preservation and disclosure on all three tabs.
- The exact disclosure is always directly below the common `craft-title`, outside
  every tab panel: **Model probability uses published PoE2DB table weights, not
  verified game odds.** Its five translations retain the distinction between
  published model weights and unverified actual game odds.

No dependency or lockfile change. Rollback is the implementation commit range;
the harmless locale preference can remain and no data migration is needed.

## Verified terminology and limits

Source path mapping was verified on actual pages, not inferred from locale codes:
`en → us`, `ko → kr`, `zh-CN → cn`, `zh-TW → tw`, `ja → jp`, `es → sp`.
[English Transmutation](https://poe2db.tw/us/Orb_of_Transmutation) and
[Korean Transmutation](https://poe2db.tw/kr/Orb_of_Transmutation), for example,
both identify `Metadata/Items/Currency/CurrencyUpgradeToMagic`; Korean is
`진화의 오브`. The supported Solar base's metadata is
`Metadata/Items/Amulets/FourAmulet9`, not a translated display string.

Collection was restricted to the 144 active service IDs (118 implemented plus 26
pending catalysts) and nine supported bases. Deferred IDs are filtered from the
source evidence scope; localization does not enable any material.

identifiers against English. Nine base pages additionally match exact metadata.

Unverified special/implicit modifier text, multi-stat variable source-unit
rendering, detailed source assumptions, certain legacy explanatory fragments,
backend error/reason messages and imported item text retain their original
English. Ordinary affix templates are now verified as detailed below. A
localized coverage notice explains the remaining fallbacks on every tab.
English-only text import remains the supported parser contract; choosing Korean
does not pretend Korean clipboard text can be parsed. Localization is not a game
mechanic, a probability validation, or a native-speaker terminology review.

## Verified ordinary modifier extension

The frontend-only `localizedModifiers.ts` adapter now translates ordinary affix
range displays in Workbench (including Alt), Explorer cards/outcome summaries,
and Support manual choices/family examples. All **1,485 ordinary definitions**
across the nine catalog bases have verified templates in **all six locales**;
792 distinct source templates per locale are centrally stored in
`modifierTemplates.json`. See
[modifier provenance and exact gaps](evidence/i18n-modifier-sources-2026-10-04.json).

Actual public PoE2DB class pages expose a `ModsView` data table. The source
collector reads Amulets, Gloves_str, Bows, Wands, Body_Armours_str, Sceptres,
Belts, Rings and Helmets_str under verified us/kr/cn/tw/jp/sp paths. English
catalog identity is resolved through retained canonical code/hover evidence or
an unambiguous generation + family IDs + required-level match, corroborated by
unchanged English stat text. Locale joins require a unique stable structural
signature: generation, family IDs, required level, eligibility tags and numeric
spans. Translated display names never identify a modifier. Numeric source spans
must match exactly, and stale API text/stats cause conservative English fallback.
The collector only exports existing catalog IDs; it changes no spawn weights,
supported materials or exclusions. Reproduce with
`node scripts/collect-i18n-modifiers.mjs <owned-cache-directory>` from repo root.

Single-stat rolls translate around the same numeric value as `rolledText` and
use locale formatting; Alt retains original ranges. Multi-stat variable rolls
continue the existing source-unit/ID rendering, localizing only the verified
affix name. No display-unit conversion or probability is inferred. The existing
scaled Iron Ring implicit special branch is preserved. All 37 uncovered special
or implicit definitions, source evidence/catalyst precision detail, some legacy
fragments and server reason/error text remain English. Clipboard import remains
English-only. Spanish Refined Necrotic name/description and ordinary Necrotic
description remain unverified; no official names were invented.

Additional regression tests cover six-locale completeness, numeric/range
preservation, stale/unknown-ID fallback, multi-stat source units and unsupported
implicit fallback. They are added but **not executed** while the parent owns
the Docker QA slot. Updated read-only TypeScript diagnostics and source-format
checks pass. No build, Docker or browser execution has occurred for this extension.

Integration retains the same two overlap files. On `CraftingPage.tsx`, preserve
the parent's new omen candidate/composition logic and its numeric projections,
then use `localizedModifierText(d, values)` for ordinary display and
`localizedModifierText(d)` for Alt. Do not replace `rolledText` inside engine,
clipboard, API, grouping or film code. Both i18n suites and the parent's omen
tests must run in the granted isolated Docker QA project after integration.
