## 14. 코드·문서 반영 및 검증 원칙

1. 사용자가 이 표를 분류하면 해당 ID에 사용/제외/조건을 반영한다. 임의의 “좋은 제작” 가치판단을 추가하지 않는다.
2. 사용자 정의 정책으로 후보 행동을 줄이는 것과 게임에서 불가능한 행동을 제외하는 것은 별도로 관리한다.
3. 허용한 화폐의 실패 결과를 삭제한 뒤 나머지 확률을 다시 100%로 만드는 방식은 사용하지 않는다. 행동을 제한해도 선택한 행동의 실제 결과 분포는 보존해야 한다.
4. 수정 후 테스트는 **사용자가 허용한 화폐 전체를 대상으로 depth를 낮춰서** 수행한다. 테스트 편의를 위해 화폐 몇 종만 임의로 남기지 않는다.
5. 미지원 재료는 지원 완료라고 표시하지 않는다. 구현·검증되지 않은 범위를 별도로 보고한다.
6. 동일한 낮은 depth에서 결과·상태 수·메모리를 비교하는 것은 검증 제안이다. 측정하지 않은 개선율을 기록하지 않는다.
7. 문서는 사용자 승인 정책을 반영한 확정본이다. 코드 수정·테스트·배포는 아직 수행하지 않았다.
