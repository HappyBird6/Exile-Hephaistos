# 제작 지원 작업 카드·시나리오 코드·아이템 그래프 구현 검증

## 구현 범위

같은 시작 상태와 제작 목적의 Exalted/Chaos 및 징조 변형을 작업 카드로 묶었다. 각 변형은 원래 method ID, 확률, 준비 비용과 반복 비용을 유지하며 비교 영역에서 따로 선택한다. 서로 다른 방법의 확률을 합산하지 않는다. 카오스는 기존 속성 제거 후 새 속성 획득으로 설명하며 필요한 준비 작업도 구분한다. 경로 선택 드롭다운 역시 작업별 비교 영역으로 바꿨다.

그래프의 실제 상태 노드는 아이템 카드다. 희귀도·아이템 종류·옵션과 수치를 직접 표시하고, 선택 경로의 이전 상태와 비교해 추가·변경·제거를 표시한다. 부모가 여러 개인데 경로를 선택하지 않았다면 변경 내역을 추측하지 않는다. 접힌 결과 후보는 하나의 아이템이 아니라는 문구를 표시한다. 서로 양립하지 않는 후보 옵션을 하나의 아이템처럼 합치지 않는다.

계산 시작과 설정 접힘 상태를 분리했다. 계산 후 설정을 자동으로 접거나 포커스·스크롤을 결과로 이동하지 않는다. 수동 접기·펼치기는 입력과 계산 결과를 변경하지 않는다. 설정 영역은 상단 전체 내비게이션과 같은 좌우 정렬을 사용한다. 정책 버튼은 오른쪽으로 이동했고 위쪽에는 시나리오 코드 입력과 복사·검증 동작을 배치했다.

## 시나리오 코드 계약과 임시 판단

- 형식은 `EHSC1/2.<SHA-256>.<gzip/base64url>`이다. v1 원본 JSON, v2 정확한 확률 구간·방법 참조 테이블, v2 표시 카드 헤더·옵션 참조까지 공유한 후보를 실제 gzip 크기로 비교해 가장 짧은 것을 내보낸다. 기존 v1 및 카드 공유 전 v2 코드도 읽는다. URL이나 서버 저장 ID 조회 기능은 만들지 않았다.
- 시작 상태·목표 AST·원본 결과와 확률 구간·경로·선택 상태·N·버전 및 6개 언어 표시 스냅샷을 포함한다. 원문 아이템 입력 문자열·소유자 쿠키는 넣지 않는다. 서버 job ID와 clientRequestId는 익명 UUID로 치환한다. 이는 서버 접근 식별자 제거이며 아이템/확률 데이터는 바꾸지 않는다.
- COMPLETE/PARTIAL의 안정된 결과와 선택 상태에서 350ms debounce로 자동 생성한다. 생성 시각과 종결 상태를 표시한다. 진행 프레임마다 재생성하지 않으며 새 입력·결과 변경·취소 시 오래된 자동 코드를 폐기한다.
- 사용자가 편집하거나 붙여 넣은 코드는 자동 결과로 덮어쓰지 않는다. 최신 결과 코드로 바꾸기는 명시적 버튼으로만 한다.
- 가져오기는 검증 후 미리보기, 그 다음 읽기 전용 열기 순서다. 서버 API 재계산이나 현재 카탈로그 대체 없이 복원한다. 명시적으로 연 코드만 sessionStorage에 보관해 새로고침을 지원한다. 원래 편집기와 localStorage 입력은 보존하고, 내 시나리오로 복사할 때만 교체한다.
- 클립보드 실패 시 입력창 직접 선택·복사와 같은 코드의 파일 다운로드를 제공한다. 공유 코드는 누구나 읽을 수 있고 회수할 수 없다. 체크섬은 손상 검출이며 작성자 인증이 아니다.
- 방어적 한도: 압축 2MiB, 해제 16MiB, 텍스트 2,800,000자, 상태 5,000개, 방법 256개, 총 결과 100,000개, 구조 깊이 32. 초과는 명시적으로 거부하며 잘라서 성공 처리하지 않는다. 최대 동시 해제 2개, 스트리밍 해제 중 상한을 검사한다.
- 알 수 없는 버전·필드, 중복/잘못된 참조, 음수/비유한 수, 잘못된 분수·확률 구간·완료 질량, 위험 키 및 비정규 JSON을 거부한다. 현재 automatic-v1의 dyadic 구간 계약만 허용한다. 코드를 실행하지 않는다.

## 자체 검토에서 수정한 사항

1. 목표 표시 이름이 export에 전달되지 않던 누락을 연결했다.
2. ES target에 없는 `findLast`를 현재 대상에 맞는 역순 검색으로 바꿨다.
3. 새 결과 생성과 늦은 완료/cleanup이 섞여 이전 코드를 최신 결과처럼 표시하지 않도록 소유자 식별과 취소 처리를 넣었다.
4. 저장된 코드 복원 중 새 붙여넣기를 덮어쓰지 않도록 세대 번호를 확인한다. 서로 다른 코드를 연속으로 열 때 결과 컴포넌트를 새 스냅샷으로 재설정한다.
5. 내 시나리오로 복사 도중 저장 실패 시 이전 입력 복원을 시도하고 편집기를 유지한다. 브라우저 저장소 자체가 복원을 거부하는 상황까지 원자적 성공을 보장한다고 주장하지 않는다.
6. 저장 아이템이 있으나 원문이 빈 경우 기본 일반 아이템이 입력을 덮어쓰는 초기화 조건을 수정했다.
7. 화면 검사로 확인한 코드 입력창 높이 우선순위와 모바일 그래프 카드 폭을 조정하고 겹친 작업 라벨을 분리했다.

### 새 화면의 의미

상태의 속성 구성과 품질·희귀도·기타 아이템 조건을 기준으로 화면만 묶는다. 랜덤 티어는 화폐 이름 allowlist에 의존하지 않는다. 같은 속성의 수치·티어 차이를 후보 안에 보관하고 후속 경로에서도 개별 티어 노드로 다시 풀지 않는다. 에센스가 보장하는 속성 값은 별도 보존한다. 준비 단계에 에센스가 들어갔다는 이유만으로 이후 엑잘·카오스의 랜덤 획득까지 확정 취급하지 않는다.

원본의 에센스 결과와 같은 실제 상태로 REGAL도 도달할 수 있다. state1의 냉기31–35 및 state11의 카오스16–19는 에센스 확정 방법의 별도 결과이므로 각각 표시한다. 그 외 냉기7개와 카오스5개는 후보 카드로 묶는다. 말단 48개는 35+7+1+5개 후보의 4개 카드로 표현한다. 별도 에센스 획득값까지 무조건 합쳐 버리지 않는다.

각 후보 카드는 공통 아이템 정보와 가능한 속성을 표시한다. 미확정 수치는 말줄임으로 표시하고 펼치면 정확한 티어와 값이 보인다. 정확한 전체 아이템 후보 및 각 원본 source/method의 확률을 선택할 수 있다. 여러 후보의 속성을 합성한 가짜 확정 아이템이나 임의 확률 합산을 만들지 않는다. 후보 선택은 정확한 원본 상태 ID와 경로를 사용하며 오른쪽 아이템과 일치한다. 대상 없는 LOSS는 아이템 수에 포함하지 않고, 대상 아이템이 있는 말단은 DEAD를 포함해 보존한다. 원본 확률 bounds는 재정규화·변경하지 않는다.
