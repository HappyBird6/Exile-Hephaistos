# 빈 희귀 아이템의 확률 획득·429·장비군 일반성 후속 리뷰

제품·테스트 커밋은 `c61a6ad934097eac1c9406895526119909fb1c38`이다. Backend 843+8개, Frontend 2221개 검사가 통과했다. localhost 서비스 교체는 범위 명확화 후 한 번의 재검토에서 승인되어 완료했다. 실제 JAR·JS 해시, readiness, 429 Retry-After와 기존 데이터 보존을 확인했다.

이 보고서는 `crafting/goal-directed-planner`의 후속 수정과 검증을 기록한다. 이전 보고서의 성공 수치를 최신 소스의 결과로 대신 사용하지 않는다. 원격 push·merge·배포는 하지 않는다.

## 수정한 원인

1. **준비 경로 누락:** 엑잘 자체에 목표 획득 가능성이 있으면 같은 화폐를 준비 단계로 쓰는 경로까지 제외했다. 빈 명시속성 상태에서 실제 카오스 후속 작업이 가능한 준비 경로는 별도로 보존한다. 소환수·+3·목걸이 ID로 경로를 선택하지 않는다.
2. **준비 후 반복:** 엑잘/제왕 준비는 한 번만 청구한다. 단일 비분열 옵션을 완전히 제거한 뒤 동일한 후보 분포가 되는 상태만 동등하게 처리한다. 제거 가능성, 징조, 품질과 보존 조건을 실제 kernel 계획으로 확인한다. 상태가 다르면 무조건 독립 시행으로 바꾸지 않는다.
3. **예산 사용:** 같은 상태로 향하는 전이를 Fraction으로 합산한다. 비교용 캐시는 64개로 제한하고, 증명된 반복 상태의 완전한 전이 분포 한 개를 재사용한다. 후속 제거 징조가 적용 불가능한 준비 결과는 후속 화폐를 청구하지 않고 종결한다. 종결 실패만 압축하며, 목표·진행 상태의 실제 아이템은 유지한다. 탐색 예산과 허용 화폐 목록은 늘리거나 줄이지 않았다.
4. **일반성:** 기존 `RollPartition.compile`은 Solar Amulet 외 장비의 안전한 단일 속성 수치 구간도 모두 개별 수치로 펼쳤다. 검증된 카탈로그의 목표식·속성군·수치 경계로 안전성을 판단하도록 확대했다. 아직 검증 범위가 좁은 tier/orbit 최적화의 Solar 제한과 품질의 보수적인 처리 등 실제 모델 제한은 유지했다. 서로 같은 제거 후 후보 분포를 준비 결과마다 다시 검사하는 중복도 제거했다.
5. **화면:** 준비 1회와 반복 화폐 최대 N회를 분리한다. 남은 반복 질량은 임의의 옵션을 가진 아이템으로 표시하지 않고 `N회 안에 목표 미달성`으로 표시한다. 목표 도달 결과는 실제 아이템으로 선택할 수 있다.
6. **429:** 실제 localhost 응답은 `429 / JOB_CAPACITY`였다. 유효한 저장 작업 16개가 전역 한도 16개를 모두 차지했고 기존 응답에는 Retry-After가 없었다. 최초 만료까지의 Retry-After를 추가했다. UI는 입력 보존, 보관 기간 만료 후 재시도, 계산 중단만으로 슬롯이 비워지지 않음을 안내한다. 같은 생성 요청은 공유하고 다른 생성 요청도 직렬화하여 owner cookie 경합을 줄인다. 이미 전송한 POST의 결과가 불확실할 때 자동 재전송하지 않는다.

## 확률과 반복의 의미

빈 RARE Solar Amulet, ilvl 82, Spirit implicit 15, 목표 RARE·소환수 스킬 레벨 ≥3의 일반 엑잘 1회 확률은 약 0.05922206%다. 엑잘 준비 후 카오스를 최대 100/300/500회 사용하는 방법은 준비 중 성공도 첫 성공으로 인정하며, 엑잘은 정확히 한 번만 청구한다. N은 준비를 포함한 총 화폐 수가 아니다.

|---:|---:|---:|---:|
| 1 | 0.11840905% | 1 | 0.999408 |

동일한 제거 후 후보 분포가 증명된 경우에만 유한 반복 분포를 재사용한다. 실제 카탈로그의 모든 후보와 미지원 질량을 분모에 보존한다. 별도의 작은 테스트 카탈로그에서는 1:3 가중치로 `1-(3/4)^(N+1)`과 카오스 기대 사용량 `Σ(3/4)^k`를 직접 대조한다. 제거할 접두 옵션이 없는 경우에는 성공 1/4, 종결 실패 3/4, 카오스 비용 0을 별도로 검증한다.

다른 장비군은 미지원 복합 수치 분포가 포함돼 탐색을 끝내도 전체 확률을 확정하지 못할 수 있다. 이 결과를 COMPLETE나 성공 확률 100%로 바꾸지 않는다. 전역 최적성을 주장하지 않는다.

## 화면 검증 방식

기존 `exile-workbench-browser:20261002`의 Chromium을 새로운 브라우저 context로 실행했다. 새 패키지 설치나 사용자 프로필·보안 설정 변경은 없었다. 최종 프런트 번들을 표시하고, 자동 탐색 응답은 격리된 실제 backend 서비스 검사에서 저장한 fixture를 사용했다. 실제 사용자의 저장 작업을 만들거나 재개하는 공개 HTTP E2E와는 구분한다.

확인 항목: 엑잘 1회→카오스 N회 표시, N=100/300 전환, 목표 아이템 선택, 미달성 질량을 가짜 아이템으로 표시하지 않음, 새로고침 GET 복원과 생성 POST 1회, 429 안내 및 자동 POST 재시도 없음. 375px viewport에서 우측 inspector 폭/scrollWidth는 모두 317px, 본문 16px였다. 캡처 이미지를 직접 확인했다. 기존 엑잘 결과 그룹도 최종 번들로 다시 열어 개별 상세와 마지막 행까지의 스크롤을 확인했다. 결과 그룹 폭/scrollWidth는 모두 317px, parent overflow는 auto, 본문 16px이며 가로 넘침이 없었다.

## 임시 판단과 남은 한계

- 기존 저장 한도 16개와 보관 정책은 유지한다. 저장 공간이 꽉 찬 상태의 정상적인 429 자체를 삭제나 한도 상향으로 감추지 않는다.
- 기존 사용자 작업·원문·환경 설정·DB·Redis는 보존한다. 이전 계산 모델 checkpoint는 새 모델로 조용히 이어 계산하지 않고 기존 409 재계산 복구 흐름을 사용한다.
- 준비 중 의도한 목표가 먼저 완성되면 성공으로 끝내며 추가 카오스를 사용하지 않는다.
- 검증 대상 반복 지평은 기존 1/100/300/500을 유지한다. 최대 명시속성 4개는 반복 횟수와 별개다.
- 확률은 저장된 카탈로그 weight 정책과 명시된 모델의 값이다. 공개 weight가 없는 부위의 승인된 균등 후보 정책을 실제 게임 확률로 확정하지 않는다.
- 복합 수치·검증되지 않은 분열/징조 조합과 품질의 미지원 질량은 미지원으로 남긴다.
- 다른 장비군 검증에서 처음 발견한 예산 중단과 후속 수정 이력도 보존한다. 최종 표에는 최종 소스에서 재실행한 결과만 넣는다.

### 429는 언제 해소되는가

`AutomaticSearchService.create`는 생성 시 `expires = 생성 시각 + 24시간`으로 저장한다. 모든 저장 상태가 전역 한도 16개에 포함된다. 현재 상태 집계는 COMPLETE 11개, CANCELLED 3개, PAUSED 2개다. READY·PARTIAL도 동일하게 포함된다. 완료나 취소는 슬롯 삭제가 아니며, GET·ADVANCE·RESUME·CANCEL·save에는 만료 시각을 갱신하는 코드가 없다.

현재 최초 만료는 **2026-10-19 16:10:43.422 UTC**(한국시간 2026-10-20 01:10:43.422)다. 사용자는 UI에 표시되는 시각이 지난 뒤 **‘다시 계산’으로 설정을 열고 제작 시작을 다시 실행**하면 된다. 단순 대기만으로 자동 재요청·자동 재개되지는 않는다. 새 생성 요청은 만료 파일을 먼저 정리하고 그 뒤 한도를 검사한다. 429는 만료 시간을 연장하지 않으므로 이 용량 조건 때문에 영구적으로 막히지는 않는다. 다른 요청이 빈 슬롯을 먼저 사용했다면 새 Retry-After를 따른다.

실제 작업은 건드리지 않고 고정 시계와 메모리 저장소로 5개 상태를 섞은 16개 fixture를 검증했다. 24시간 만료 1초 전은 429·Retry-After 2초이며 내용이 보존됐다. 만료 1초 후 새 요청은 성공하고 새 작업 1개만 남았으며 새 만료는 그 생성 시점부터 다시 24시간이었다. 추가한 `capacityExpiresAfterFixedTtlForEveryStoredStatus`를 포함해 해당 테스트 클래스 5개가 모두 통과했다. 전체 제품 검사 843+8개 이후 테스트만 추가했으므로 이를 전체 844개 재실행으로 표현하지 않는다.

추가 증거: `empty-deployment-verification.json`, `empty-capacity-after.json`, `empty-live-browser-results.json`, `empty-ttl-tests.xml`, `empty-ttl-tests.log`. 원격 push·merge·배포는 하지 않았다. 남은 실행 차단은 없다.
