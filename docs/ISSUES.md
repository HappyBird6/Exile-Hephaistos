# 제작지원 경로 탐색 이슈

2026-11-25 기준 두 건 모두 미해결이다. 재현 기준 커밋은 `05b27f2f`이며, 두 요청 모두 테스트 탭의 `POST /api/v1/crafting/support/goal-filters/test-routes`를 사용했다. 아래 경로 수는 이 커밋의 관측값이다.

## 1. 희귀 시작에서 배포 JRE가 훼손 경로를 모두 탈락시킴

1. **재현 조건.** 아이템 레벨 82, 명시 옵션이 없는 희귀 태양 목걸이에서 정신력 47 이상, 일반 방어력 증가(에센스), 모든 투사체 스킬 레벨 +3 이상을 함께 선택한다.
2. **확인된 결과.** 같은 JAR와 입력에서 개발 JDK는 경로 48개(일반 24개, 럭키 24개)를 반환했다. 개발 JDK에서 `jdk.random`만 제외하거나 저장소에 고정된 배포 JRE로 실행하면 모두 HTTP 200, 목표 카드 1개, 경로 0개, `complete: true`였다. 세 종류의 쇄골은 각각 108번 평가됐고 생성된 결과는 각각 0개였다. 예산 때문에 건너뛴 상태는 0개였다.
3. **확인된 원인.** 배포용 Temurin 21.0.12.1+1 JRE의 실제 모듈에 `jdk.random`이 없다. 뼈의 방향과 제거 대상을 이미 지정한 경로에서도 `DesecrationCurrency.apply`가 `RandomGenerator.getDefault()`를 먼저 호출한다. 기본 알고리즘 `L32X64MixRandom`을 찾지 못해 발생한 `IllegalArgumentException`을 탐색기가 해당 방향의 뼈 사용 불가로 처리한다. 그 결과 미공개 슬롯이 생성되지 않아 드러내기까지 도달할 수 없다. ## 2. 일반 시작에서 첫 L을 얻는 경로가 모두 럭키로 표시됨

1. **재현 조건.** 아이템 레벨 82, 명시 옵션이 없는 일반 태양 목걸이에서 정신력 47 이상, 일반 방어력 증가(에센스), 냉기 저항(수치 미지정)을 선택한다.
2. **확인된 결과.** 반환된 100개 경로 모두 럭키였고, 럭키 표시를 끄면 0개였다. 카오스와 훼손 후보는 평가됐다. 이 요청은 `complete: false`였고 예산 때문에 건너뛴 상태가 30,096개였다. 하급 해동의 에센스도 후보에 포함됐다. 비럭키 경로가 처음 사라지는 단계와 예산의 영향은 추가 확인이 필요하다.
3. **사용자 관찰.** 진화에서 정신력 47을 얻은 뒤 승급 에센스로 목표 냉기 저항을 붙였는데, 이후 방어력 에센스 단계에서 냉기 저항을 더미처럼 취급하고 엑잘로 다시 얻는 경로가 표시됐다. 단계별 실제 아이템과 목표 획득·손실 기록을 대조해야 한다.

## 수정 순서와 완료 기준

1. **배포 JRE에서 뼈 사용을 복구한다.** 이미 정해진 방향과 제거 대상을 적용할 때는 난수 생성기를 열지 않는다. 작업대에서 실제 추첨이 필요할 때는 배포 JRE에서 지원하는 생성기를 사용한다. 개발 JDK와 고정 배포 JRE에서 1번 요청을 비교해 비럭키 완주 경로, 뼈 사용, 별도의 드러내기 단계를 확인한다. 작업대의 무작위 제거·방향 선택도 검증한다.
2. **첫 L 획득의 두 분기를 따라간다.** 진화에서 정신력 47을 얻으면 럭키 분기로 진행한다. 빗나가면 희귀 승급 후 필요할 때만 소멸로 교체 가능한 옵션을 하나 남기고, 같은 베이스에서 카오스로 목표 티어까지 반복하는 비럭키 분기를 추적한다. 두 분기의 후보 생성·후속 상태 채택·예산 소진을 비교해 실제 탈락 지점을 수정한다. L/M/H 판정은 사용자가 허용한 티어들의 등장 확률 합을 쓴다.
3. **Lesser 에센스를 제작지원 후보에서 제외한다.** 카탈로그의 에센스 등급으로 판정한다. 후보 생성과 검증이 같은 정책을 사용하게 하고, 유효한 일반·상위 승급 에센스와 완벽한 교체형 에센스의 역할을 각각 검사한다.
4. **획득한 목표와 카오스 준비용 더미를 구별한다.** 승급 에센스로 의도한 냉기 저항을 얻으면 즉시 보유 목표로 기록한다. 방어력 에센스 사용 시 제거된 옵션과 살아남은 옵션을 실제 결과대로 다음 단계에 전달한다. 냉기 저항을 보유한 경로에서 다시 획득할 필요가 없어야 한다. 필요한 목표를 잃은 경우에는 손실과 기존 보존 규칙을 적용한다. 준비 중 우연히 목표가 붙은 경로에만 해당 적중의 럭키 표시를 붙인다.
5. **훼손 목표를 남은 옵션의 획득 난이도로 고른다.** 첫 L은 가능한 경우 카오스 반복으로 확보한다. 남은 L·M·H 중 엑잘 추첨이 필요한 목표는 실제 공개 후보와 슬롯을 확인해 훼손을 우선 배정한다. 여러 목표가 가능하면 등장 확률이 낮거나 다른 수단으로 붙이기 어려운 쪽을 우선한다. 훼손으로 얻을 수 없는 새 L에는 완벽한 엑잘 시도를 고려한다. 뼈는 조건을 만족하는 시점에 쓰고, 드러내기는 다른 목표를 얻은 뒤 마지막에 한다. 제작지원은 적격 목표의 공개를 100%로 계산하며 뼈 사용의 방향·제거 위험은 별도로 계산한다. 필요한 신성한 오브는 공개 뒤에 둔다. 빛의 징조 반복은 사용하지 않는다.
6. **API와 화면에서 같은 결과를 검증한다.** 두 재현 요청 모두 럭키 표시를 끄고 완주 경로를 확인한다. 일반 시작에서는 럭키를 켜 진화 적중 분기도 확인한다. 단계별 목표 획득·손실, Lesser 사용 0건, 뼈와 드러내기의 분리, M/H 훼손이 유리한 다른 베이스 사례까지 검사한다. 검증된 제작 정책은 [제작지원 경로 규칙](v0.5.5/game-rule/support-test-routes.md)에 반영한다.
