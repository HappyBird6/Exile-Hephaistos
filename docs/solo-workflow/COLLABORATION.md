# 역할·세션·협업

상위: [공통 규칙](MULTI_SESSION_WORKFLOW.md). 양식: [RECORDS.md](RECORDS.md).

## 역할과 이름

| 역할 | 권한 |
|---|---|
| manager | 사용자 창구, 작업 분류·배분, 직접 구현·테스트, 기록 단일 작성, Git 통합·허용된 원격 작업 |
| worker | 배정된 범위 구현·테스트·자기 commit, 자기 결과 파일 작성 |
| reviewer | 고정된 대상 읽기, 명세·품질 판정, 자기 결과 파일 작성. 코드 변경·중복 테스트 실행 안 함 |

각 세션은 최초 실행 시 `<프로젝트표시명>-<역할>-<작업ID축약>-<번호>`로 자기 표시 이름을 정한다. 기존 프로젝트 명명 규칙이 명시되어 있으면 우선 적용한다. 이름 변경 도구가 있으면 실제 제목도 바꾸고 없으면 논리 이름만 기록한다.
역할은 사용자 또는 관리자의 위임에서 얻는다. 도구의 실제 ID를 기록하며 모르면 null로 둔다. 논리 ID는 주소가 아니다. 관리자가 생성 결과의 ID와 작업자의 자기 보고를 대조해 sessions.json에 등록한다. 작업자는 등록부를 직접 수정하지 않는다.
동일 이름이어도 실제 ID가 다르면 별도 세션이다. 대체 세션은 이전 ID·인계 시각·종료 확인 근거를 남긴다. 작업자가 idle이거나 검색에서 안 보인다는 이유만으로 소유권을 회수하지 않는다.

## 전달 절차

1. 관리자가 task ID, 메시지 ID, 대상 실제 세션 ID, 지침 위치, 파일 소유권, 기준 SHA, 필요한 요구사항·계약, 결과 경로를 전달한다.
2. 작업자는 접수 상태를 반환한다. `(task_id, message_id)`가 같으면 기존 결과·진행 상태를 돌려주고 재실행하지 않는다. 수정 요청은 새 메시지 ID와 원 요청 ID를 사용한다.
3. 작업자는 자기 결과 파일에 상세 내용을 저장하고 관리자에게 상태·SHA·검증 요약·결과 경로만 보낸다.
4. 관리자는 도구 결과와 실제 산출물을 대조해 진행 상태를 갱신한다. 결과가 누락된 세션만 확인하고 전체 목록·전체 기록을 반복 조회하지 않는다.

다른 기능의 변경이 필요하면 관리자에게 요청한다. 작업자끼리 재위임하거나 상호 대기 고리를 만들지 않는다. 관리자는 기존 담당에게 전달하거나 순차 처리한다. 새 요청은 기본 접수 순으로 처리하고 명시적인 사용자 긴급 지시만 우선한다.

## 환경 분리

worktree는 파일만 분리한다. 테스트 포트는 비어 있는 포트를 할당하고 DB/schema/cache/임시 파일은 task ID로 분리한다. 분리할 수 없는 테스트는 관리자가 순차 실행한다. 운영 자격증명으로 테스트하지 않는다.
읽기 리뷰에는 새 브랜치를 의무화하지 않는다. 검토 대상 파일이 바뀌지 않도록 고정 SHA의 diff/파일을 제공하고 쓰기 작업과 겹치지 않게 한다.

## 관리자 단일 작성과 복구

프로젝트당 활성 관리자 하나만 공용 상태를 쓴다. 최초 취득은 공용 기록 디렉터리의 manager.lock을 원자적 배타 생성하거나 동등한 OS 잠금으로 수행한다. 다른 관리자 잠금이 있으면 takeover하지 않는다. 소유 세션 ID·실행 식별자·취득 시각을 기록한다.
정상 종료 때 자기 잠금만 해제한다. 중단 후 잠금이 남으면 이전 프로세스 종료나 명시적 인계가 확인된 경우에만 회수한다. 확인할 수 없으면 상태 불명으로 보고한다. 단일 작성은 잠금이 필요 없다는 뜻이 아니다.
재개 시 공통 규칙, config, 현재 작업 기록, 실제 Git 상태, 미완료 결과만 읽는다. 완료 commit이 있으면 재구현하지 않는다. 실행 결과가 불명확한 push·migration 등은 상태 확인 전 재실행하지 않는다.
협업 도구가 사라지면 실행 중 작업자의 종료·소유권을 먼저 확인한다. 확인 전 동일 파일 작업을 단일 세션이 대신 시작하지 않는다. 시간 초과는 `STATUS_UNKNOWN`으로 기록하고 안전한 독립 작업만 계속한다.
