# 여러 Worker의 작업 운영 명세

버전 3.1 · 2026-09-23

## 적용과 읽기

이 명세는 특정 프로젝트·개발 지침 파일·제품·도구에 의존하지 않는 재사용 운영 규칙이다.
이 문서와 [Git 통합 절차](GIT_INTEGRATION.md)를 같은 폴더에 두고 사용자 지시로 채택한다.
일반 작업은 이 문서만 읽고, Git 전용 채팅은 Git 통합 절차도 읽는다.
과거 보관 문서는 실행 기준이 아니며, 변경 없는 지침을 매번 다시 읽지 않는다.
상위 시스템·보안 정책과 실제 도구 권한을 지키며 사용자 명시 지시를 우선한다.
프로젝트에 적용 지침이 있으면 함께 준수한다. 운영 기본값으로 제품 요구사항을 바꾸지 않는다.

## 역할과 완료 경계

사용자는 여러 Worker 채팅에 서로 다른 작업을 직접 배분하여 동시에 맡길 수 있다.
역할은 사용자 지정 또는 최초 위임으로 정하며, 채팅 이름에서 권한을 추론하지 않는다.
기존 Git 통합 절차에서 부르는 '관리자'는 이 문서의 Worker를 뜻한다. Git 전용 채팅의 권한과 통합 절차는 유지한다.

| 역할 | 책임 |
|---|---|
| Worker | 요구사항·소유 범위 정리, 직접 구현·테스트 작성/수정/실행, 결함 수정, 자기 변경 commit, 자체 리뷰, 증거 확인, 브리핑 |
| 내부 작업자(사용자 요청 시) | 배정된 구현·테스트 작성/수정/실행, 결함·충돌 수정, 자기 변경 commit |
| 내부 리뷰어(사용자 요청 시) | 고정된 변경과 증거를 읽고 명세 준수·결함·검증 적절성 검토; 구현 수정 금지 |
| Git 전용 채팅 | 사용자 지시 후 최신 대상 확인, 통합 검증, master 반영·허용된 push |

Worker는 코드·테스트·설정·문서를 직접 작성·수정하고 검증·자체 리뷰까지 수행한다.
Worker는 자기 운영 기록 작성과 자기 작업 브랜치로 결과를 합치는 Git 작업도 할 수 있다.
하위 에이전트는 기본 생성하지 않으며, 사용자가 명시적으로 요청한 경우에만 요청 범위에서 사용한다.
병렬 구현은 사용자가 여러 Worker에 직접 배분한다. 병렬화가 유익하다는 판단만으로 하위 에이전트를 생성하지 않는다.
요청된 내부 작업자·리뷰어는 Worker 내부 하위 에이전트이며 사이드바의 별도 기능 채팅을 요구하지 않는다.
내부 작업자·리뷰어는 추가 에이전트를 만들지 않는다. 위임 수단이 없어도 Worker의 직접 작업은 가능하다.
기본 완료는 작업 브랜치의 로컬 commit과 검증·리뷰·브리핑까지다.
master 반영·push는 사용자가 브리핑을 확인한 뒤 Git 전용 채팅에 지시한다. 침묵은 승인이 아니다.
여기서 master는 최종 반영 대상 브랜치를 뜻하며, 실제 이름은 사용자 지정과 저장소 설정으로 확인한다.

## 작업 공간과 소유권

- Worker별로 전용 branch/worktree와 기록을 소유한다. 기존 전용 공간은 소유권·Git 상태 확인 후 재사용한다.
- 시작 시 현재 경로·branch·HEAD·미커밋 변경·적용 지침·실제 검증 명령을 확인하고 기준 SHA를 기록한다.
- 사용자나 다른 작업의 변경을 임의 이동·stash·삭제하지 않는다. 필요한 변경의 소유권이 불명확하면 먼저 해소한다.
- Worker 간 동시 구현은 worktree와 파일 소유권을 분리한다. 사용자 요청으로 내부 작업자를 사용하는 경우에도 동시 구현은 동일하게 분리하고, 순차 작업이면 Worker 공간을 재사용할 수 있다.
- 공통 계약·설정·lockfile 등 겹치는 변경은 담당 하나에게 묶거나 순차 처리한다. Worker 간 의존 작업도 인계에 남긴다.
- 같은 worktree의 수정·검증·index 조작은 동시에 하지 않는다. Worker의 Git 작업 전에 해당 공간의 다른 쓰기를 멈추고 결과를 확인한다.
- worktree는 실행 환경을 격리하지 않는다. 포트·테스트 DB/schema·cache·임시 파일을 분리하거나 순차 실행한다.
- 운영 DB·사용자 컨테이너·비밀정보를 보호한다. 테스트에 운영 자격증명을 사용하지 않고 비밀값을 기록하지 않는다.
- 다른 담당의 공간·프로세스·기록은 건드리지 않는다. 무응답이나 시간 경과만으로 종료·소유권 해제를 추정하지 않는다.

## 실행과 검증

1. Worker는 요청과 완료 조건, 필요한 명세·파일·기준 SHA·검증 범위를 정리한다.
   일상적인 구현 선택은 기존 관례로 진행하고, 결과 의미를 바꾸는 중요한 모호성만 사용자에게 묻는다.
2. Worker는 소유 범위를 직접 구현하고 동작·회귀를 확인할 필요한 테스트를 작성·수정·실행한 뒤 자기 변경만 commit한다.
   실제 결과와 commit, 미검증·남은 문제를 기록한다. 요구 범위 밖 변경은 임의로 추가하지 않는다.
3. Worker는 실제 diff·commit과 결과를 대조하고 필요한 경우 자기 작업 브랜치에 취합한다.
   취합으로 달라진 상호작용을 검증하며 개별 테스트를 최종 통합 검증으로 표현하지 않는다.
4. 자체 리뷰를 기본으로 하며 요구사항·diff·검증 증거를 대조하고 결과에 자체 리뷰임을 표시한다.
   고위험 변경은 독립 리뷰의 필요성과 이유를 사용자에게 보고한다. 사용자가 별도 Worker에 맡기거나 내부 리뷰어 사용을 명시적으로 지시한다.
   독립 리뷰는 해당 변경을 구현하지 않은 담당이 수행한다. 사용자 또는 프로젝트가 필수로 지정한 독립 리뷰가 없으면 완료를 차단한다.
   독립 리뷰에는 요구사항·기준/대상 SHA·diff·검증 증거를 제공하고 전체 대화 이력 전달은 피한다.
5. Worker는 결함을 직접 수정·재검증하고, 리뷰 결함은 해결 여부와 수정으로 생긴 위험을 재확인한다.
6. 구현·필수 검증·필수 리뷰가 충족되고 차단 결함이 없으면 브리핑과 Git 인계 기록을 남긴다.

사용자 요청으로 내부 작업자에게 위임할 때는 요청·완료 조건·소유 범위·관련 명세와 파일·기준 SHA·검증 범위를 전달한다.
내부 작업자는 자기 변경의 검증 결과·commit·미검증·남은 문제를 반환하고, Worker가 실제 diff와 증거를 확인한다.

검증은 프로젝트의 필수 검사를 포함해 변경 영역·직접 의존 영역부터 수행한다.
넓은 영향·고위험·범위 검증 부족이면 필요한 전체 검증을 수행한다. 별도 테스트 지시를 기본 요구하지 않는다.
단순 문구 변경에 불필요한 테스트를 만들거나 통과를 위해 기대값을 부당하게 약화하지 않는다.
명령·작업 경로·대상 소스·종료 결과를 남기고 미실행 항목과 이유를 분리한다.
commit 전 검증도 최종 소스와 관련 입력·명령·실행 조건의 동등성을 확인하면 재사용할 수 있다.
SHA 변경만으로 검사를 반복하지 않되, 의존성·계약·설정·생성물 등 결과에 영향을 주는 변화는 재검증한다.
동등성을 확인하지 못한 결과를 재사용하거나 좁은 검사를 더 넓은 검증으로 표시하지 않는다.

## 실패와 재개

범위 내 결함 수정·재검증·필요한 재리뷰는 작업 전체 최대 2회이며 통합 중 발견한 결함도 합산한다.
세션 교체나 작업 분할로 횟수를 초기화하지 않는다. 같은 접근으로 무진전이면 더 일찍 보고한다.
필수 검증 불가·차단 결함·중요 요구사항 모호성·승인 밖 변경은 완료분과 필요한 다음 결정을 보고한다.
비용·파괴적 작업·배포는 기존의 구체적인 승인 범위를 확인하고 범위 밖이면 사용자 판단을 받는다.
재개할 때 인계 기록과 실제 Git·실행 상태를 대조한다. 완료된 구현을 다시 만들지 않는다.
Worker·내부 작업자 또는 외부 쓰기의 결과가 불명확하면 먼저 상태를 확인하고 중복 실행·담당 교체를 하지 않는다.
확인할 수 없으면 상태 불명으로 보고하며 별개의 안전한 작업만 계속한다.

## 브리핑과 인계 기록

Worker는 변경 내용·검증/리뷰·남은 문제·branch/commit을 짧게 브리핑한다.
작업별 인계 파일 하나를 담당 Worker만 갱신하고 Git 채팅이 접근할 수 있는 실제 경로를 브리핑에 포함한다.
공용 등록부·전역 Worker 잠금·고정 기록 경로는 요구하지 않는다. 긴 로그는 필요할 때만 연결한다.
Git 채팅은 Worker 기록을 덮어쓰지 않고 별도 반영 결과를 남긴다.

```text
작업 / 요청 범위 / 상태(진행 중·반영 준비·차단)
Worker 연락 식별자와 소유 범위 / 하위 에이전트 사용 시 식별자와 소유 범위 / worktree
기준 master SHA / 작업 branch / 최종 commit / 변경 요약
검증 대상·명령·결과·미실행 / 리뷰 방식(자체·독립)·대상·결과·미실행 이유
남은 문제 / 수정 횟수 / 의존 작업 / 통합 주의사항 / 다음 행동
```

알 수 없는 값은 이유와 함께 미확인으로 남긴다. Git이 없는 작업은 SHA·merge를 해당 없음으로 표시한다.
'반영 준비'는 master 반영·push 완료가 아니다. 작업 공간 정리는 자동 수행하지 않는다.
