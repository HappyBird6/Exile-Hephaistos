# Codex 1인 개발 운영 명세 v2.1

2026-09-22 · 진입 문서 · 기존 고정 역할 운영 가이드를 대체한다.

## 목적과 적용

사용자 요청 한 번으로 구현·검증·필요한 리뷰·범위 내 수정까지 진행한다. 사용자 개입, 중복 문맥, 세션 간 인계를 줄인다. 정확성·사용자 변경 보존·검증 증거는 유지한다.
이 묶음은 프로젝트용 운영 명세다. 설치형 SKILL.md나 세션 메시지 서버를 제공하는 제품이 아니다. 문서를 읽는 것만으로 없는 도구 권한이 생기지 않는다.

## 시작 방법

1. 이 폴더를 프로젝트의 `docs/solo-workflow/`에 함께 둔다. 파일명과 상대 경로를 유지한다.
2. Codex에 아래처럼 요청한다. 최초에 모든 설정을 채울 필요는 없다.

> docs/solo-workflow/MULTI_SESSION_WORKFLOW.md를 운영 기준으로 사용해. 필요한 설정은 자동 감지하고 기본값으로 진행해. 이번 작업은 [요청 내용].

3. 관리자는 [설정·환경](SETUP.md)을 최초 1회 읽고 감지 결과를 저장한다. 이후 환경이나 설정이 바뀔 때만 해당 부분을 재확인한다.
4. 반복 사용 시 기존 AGENTS.md를 덮어쓰지 않고 이 진입 문서를 참조하는 한 문장을 추가할 수 있다. 프로젝트 규칙과 충돌하는 부분만 조정한다.

## 공통 실행 규칙

- 관리자는 요구사항 정리·기능 세션 생성/재사용·작업 배분·검증 증거 확인·독립 리뷰 조율·Git 통합을 맡는다. 코드·테스트·설정·문서의 직접 작성·수정은 금지한다. 공용 운영 기록 작성과 통합 검증 실행은 가능하다. 상시 테스트·리뷰·Git 세션은 만들지 않는다.
- 구현이 필요한 요청은 이 흐름에 따른 사용자 위임과 실제 도구 정책 안에서 별도 기능 세션(worker)을 생성하거나 기존 담당을 재사용한다. 협업 수단이 없으면 BLOCKED로 보고하며 관리자 직접 구현으로 대체하지 않는다. 작업자는 추가 에이전트를 만들지 않는다.
- 사소한 문구·스타일·문서 변경에도 직접 구현 예외를 두지 않는다. 기본은 기능 작업자 1개이며, 독립적인 작업으로 나눌 실익이 있을 때만 동시 최대 2개 작업자를 사용한다.
- 역할은 최초 위임으로 결정한다. 각 세션이 규칙에 맞는 이름을 정하고 실제 세션 ID에 연결한다. 이름으로 역할을 역추론하지 않는다.
- 기능 작업자가 구현·필요한 테스트 작성/수정/실행·자기 변경 commit을 맡는다. 검증·리뷰 결함 수정과 내용 판단이 필요한 충돌 해결도 작업자에게 위임한다. 전체 검증은 영향이 넓거나 프로젝트 필수 절차인 경우에 선택한다.
- 독립 리뷰는 일반 기능·고위험 변경에 사용한다. 사소한 변경은 근거를 남기고 생략한다.
- 범위 내 결함은 기본 2회까지 수정·재검증한다. 범위 확대, 반복 무진전, 중요한 요구사항 모호성은 사용자에게 보고한다.
- 사용자 변경·다른 작업자의 변경을 섞거나 폐기하지 않는다. 병렬 쓰기는 전용 worktree와 분리된 파일 소유권을 사용한다.
- 동일 SHA뿐 아니라 검증 당시 작업 공간·관련 실행 조건을 확인한다. 구현 완료와 검증 통과를 구분한다.
- 기본 최종 단계는 작업 브랜치의 로컬 commit이다. PR·최종 브랜치 반영·push·배포는 저장된 승인 정책 범위에서만 진행한다.
- 상위 시스템·조직 정책과 실제 도구 승인을 준수한다. 사용자 명시 지시, 프로젝트의 적용 지침, 이 운영 기본값 순으로 해석하고 보안·권한 충돌은 임의로 우회하지 않는다. 제품 요구사항은 구현의 기준이며 운영 기본값으로 변경하지 않는다.
