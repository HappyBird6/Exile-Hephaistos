# 설정과 실행 환경

상위: [진입 문서](MULTI_SESSION_WORKFLOW.md). 결과 양식: [기록](RECORDS.md).

## 자동 감지

| 항목 | 결정 규칙 |
|---|---|
| 프로젝트 루트 | 사용자 지정 경로 우선, 아니면 현재 위치에서 `git rev-parse --show-toplevel`. Git이 아니면 현재 디렉터리를 알리고 파일 작업으로 진행. Git 생성·원격 생성은 추측하지 않음 |
| 공용 Git 위치 | `git rev-parse --path-format=absolute --git-common-dir`; 미지원이면 출력 경로를 현재 위치 기준 절대 경로로 정규화 |
| 프로젝트 ID | 정규화한 공용 Git 경로의 SHA-256 앞 12자리. 비 Git은 루트 경로 사용. 최초 저장 후 유지; 복제본은 별도 프로젝트로 취급 |
| 운영 기록 위치 | 공용 Git 디렉터리 아래 `solo-workflow/`; 비 Git은 프로젝트의 `.solo-workflow/`. 소스 commit에 운영 로그를 섞지 않음 |
| 지침 | 적용되는 AGENTS.md와 사용자가 지정한 명세를 우선 확인. 관련 디렉터리 지침만 추가 로드 |
| remote·대상 브랜치 | 명시 설정 → 현재 upstream → 유일한 remote의 로컬 symbolic HEAD 순. 모호하면 로컬 작업을 계속하고 원격 작업에 필요해질 때 질문 |
| 시작점 | 사용자 지정 참조 우선, 아니면 실제 HEAD SHA. 자동 감지한 로컬 정보가 원격 최신이라고 주장하지 않음 |
| 테스트 명령 | 지침 → CI → package/build 설정에서 확인. 명령 본문·외부 부작용도 확인. 없는 명령을 만들어 실행하지 않음 |
| 작업 ID | UTC `YYYYMMDDTHHMMSSZ` + 임의 6자리. 충돌하면 새 접미사 생성 |
| 브랜치 | `ai/<작업ID>/<역할>-<번호>`; 기존 소유 브랜치는 검증 후 재사용 |
| worktree | 루트의 형제 디렉터리 `<프로젝트폴더>-ai-worktrees/<작업ID>/<역할>-<번호>`; 충돌 시 접미사, 기존 경로 덮어쓰기 금지 |
| commit 메시지 | 기존 프로젝트 규칙 우선, 없으면 `fix/feat/docs/chore: 간결한 작업 요약` |

감지 결과는 config.json에 저장한다. 절대 경로는 로컬 기록에만 두며 인증정보·원격 URL의 토큰은 기록하지 않는다. 기록 경로에 쓸 수 없으면 승인된 다른 로컬 경로를 사용하고 그 위치를 명확히 남긴다.

## 기본값

- 관리자 1개, 동시 구현 작업자 최대 2개. 기본은 단일 실행.
- 작업 전체 자동 수정 예산 2회. 통합·리뷰 결함에도 같은 예산 사용.
- 별도 리뷰: 일반·고위험 변경. 사소한 변경은 자체 확인.
- 전체 테스트: 명시적 프로젝트 필수 조건, 넓은 영향, 고위험 변경 또는 범위 검증으로 충분하지 않을 때. 단순 편의 때문에 전체 실행하지 않음.
- 명령 실행 시간 제한: 기본 10분. 프로젝트 정상 실행시간이 더 길면 실행 전에 해당 명령만 조정하고 기록. 강제 종료 대상은 자신이 시작한 프로세스만.
- 메시지 접수 확인 기본 2분, 진행 확인 기본 10분. 정상 진행 증거가 있으면 계속 기다림. 시간 경과만으로 실패·승인·소유권 해제를 추정하지 않음.
- 로그는 파일, 대화에는 상태·결과·경로만. 전체 대화 이력 전달 금지.
- 자동 삭제 없음. 완료된 공간의 정리 후보만 보고; 사용자 정리 정책이 있을 때 보존을 확인하고 적용.

## 실제 협업 수단 점검

존재하는 도구 이름과 지원 범위를 config.json에 기록한다. 가상의 도구 이름이나 세션 ID를 만들지 않는다.

| 능력 | 확인할 내용 | 없는 경우 |
|---|---|---|
| 세션 생성·식별 | 반환되는 실제 ID, 접근 가능한 세션 범위 | 단일 세션 처리 |
| 요청·후속 지시 | ID를 대상으로 전달하는 기능 | 단일 세션 처리 |
| 결과 수신·대기 | 완료 알림 또는 상태 조회 | 신뢰 가능한 전달이 없으면 병렬 실행 안 함 |
| 파일 공유 | 작업자가 지침·자기 worktree·결과 경로에 접근 가능한지 | 공유 경로를 가장하지 않고 단일 실행 |
| 이름 변경 | 실제 채팅 제목 변경 기능 | 논리적 표시 이름만 기록; 제목 변경했다고 주장하지 않음 |
| Git·검증 | Git 및 필요한 런타임 | 가능한 파일 작업 수행, 불가한 검증은 미검증으로 보고 |

부모가 생성한 작업자 ID를 다룰 수 있다는 것이 임의의 기존 채팅을 검색·연결할 수 있다는 뜻은 아니다. 기능 부족 시 수동 전달을 기본으로 요구하지 않고 단일 세션으로 축소한다. 고위험 독립 리뷰가 불가능한 경우에는 QUALITY.md의 차단 규칙을 따른다.

## 최초 사용자 설정 최소화

목표만 있어도 기본값으로 시작한다. 기존 승인 범위가 있으면 반복 확인하지 않는다. 사용자가 바꾸고 싶을 때만 다음을 지정한다.

| Git 정책 | 허용 범위 |
|---|---|
| `local` (기본) | 자기 작업 브랜치 commit·로컬 통합 후보·검증까지 |
| `pr` | 지정 remote의 작업 브랜치 push와 PR 생성까지, merge 제외 |
| `integrate` | 지정 remote·최종 브랜치에 검증된 변경 반영·일반 push까지 |

PR 정책은 해당 호스팅 도구가 있을 때만 사용한다. 원격 대상이 모호하면 원격 작업만 보류한다. 자동 배포를 유발하는 push는 배포 허용 범위도 확인한다. 비용 발생·운영 데이터 변경·배포는 구체적인 사전 허용 범위를 저장한다. Git 정책만으로 이를 추가 승인하지 않는다. force push·사용자 변경 폐기는 기본 허용하지 않는다.
