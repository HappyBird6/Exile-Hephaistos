## All-branch safety and UI

Only Rare, catalog-valid ordinary-condition items are accepted. For **every** eligible removal and **each** of the two target outcomes, the remainder must permit the shared EssenceAbyss family and that target's affix slot. Any failing branch blocks the whole action; neither the removal set nor the target set is pruned. For example, a full prefix side left intact by suffix-only removal blocks the action even though the suffix target might fit. Prefix-only removal can free the prefix slot while still leaving room for either outcome. Both matching Crystallisation omens remain UI-prevented/backend-rejected.

A surviving existing Mark prevents addition of either same-family target. A sole eligible unlocked Mark can be replaced by either affix; a Fractured Mark cannot be removed and remains conflicting. Fractured instances and every unaffected value are preserved; only a matching Crystallisation is consumed on success. Unrelated omens remain. Normal/magic items, invalid family/slots and failed requests do not append a craft.

The existing ItemCard correctly displays the fixed sourced Mark with no invented numeric Alt range. The boundary remains visible: Mark modifier supported; desecration and revealing its result unsupported. This adds no revealed/Desecrated state, sockets, quality, new base, Support/Explorer feature, login or DB schema.
