# Certified method map integration

The existing method-depth map consumes the certified calculation through a small
atomic display view. Start-item and full goal inputs remain unchanged, including
the six existing languages. Display buckets group goal/entry progress only; every
arrow retains its full source class identity, initial actions, cycle actions and
conditional result laws. All supported alternatives remain available through paging.

Per-exit progress aggregates reuse summaries computed during cooperative result
publication. Building map cards does not enumerate or decompress their full laws.
Outcome inspection uses bounded class pages with roll, tier and orbit metadata.
Full entry-conditioned expansion remains a separate retained operator and is not
reconstructed from representative cards or family counts.

The client validates rational interval endpoints, arithmetic width and total mass
enclosure. It renders a common rounded value only when both endpoints round to it,
otherwise a range. Unresolved upper mass remains visible even if its lower bound is
zero. Initial/cycle consumption uses quantity bounds, independently of the 100/300/
500 observation selector. Local and final recommendations keep distinct styling;
recommendation styling also reaches the corresponding map arrows.

A view pins header and graph to the same job/revision. Further pages and class
inspection reject stale revisions. A fresh revision reloads the number of method
pages the user opened, rather than silently collapsing their alternatives. The
existing request identity, owner scope, generation and command replay controls
remain in force. Stopping during an automatic resume is sticky: the client cancels
the resulting running or paused generation after that control finishes.

The production certified compute lease is one million scheduler operations;
explicitly configured test/service leases keep their requested size. This is neither
primitive currency uses nor method cycles. The UI continues COMPUTE_BUDGET pauses
while the user is running the search and stops automatic continuation on other
resource/error states. Resume requests use the existing one-million-entry API
allowance. Enumeration completion and final strategy completion remain distinct:
the production final-strategy scheduler is still pending, so the display header
currently carries NOT_REQUESTED and no final strategy rows.
