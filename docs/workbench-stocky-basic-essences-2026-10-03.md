# Stocky Mitts basic Essence extension (2026-10-03, v18)

Adds the Lesser/ordinary/Greater tiers of Body, Mind, Ruin, Insulation, Thawing, Grounding and Opulence to the existing two-base Workbench. Existing Enhancement tiers and Greater Battle remain supported: 25 fixed basic Essences on Stocky Mitts. This is a bounded equipment extension, not complete game inventory coverage. No new base, normal modifier, selection weight, Catalyst, special item state, Support or Explorer feature is introduced.

## Primary evidence and implementation boundary

Current [PoE2DB strength gloves](https://poe2db.tw/us/Gloves_str) was fetched on 2026-10-03 and retained under `codex/qa-20261003/gloves-current-20261003.*`. Each of these 21 Essence rows uniquely matches an existing ordinary modifier by exact rendered effect, source level, affix type and family. Its actual `Code` was then requested through PoE2DB's public `hover?s=Data\Mods/...` endpoint. Every response was HTTP 200 and its source stat IDs, signed bounds and locality matched the bundled ordinary catalog. The source contains explicit gloves/armour applicability. Full row/detail proof is [basic-essence-proof.json](../backend/src/main/resources/catalog/stocky-mitts/basic-essence-proof.json), SHA-256 `763b30940b76cdcbe4938c1ef2f980821fd90452676bbf91961f5b43e8f19329`. No invented hover keys or alternate glove classes are used.

Existing sourced basic Essence effect is Magic -> Rare with one guaranteed modifier; ordinary random additions are not performed. Complete single-target sets have selection probability 1, not ordinary spawn-weight sampling. Their source endpoints are verified; Stocky numeric interior distributions remain the explicit WB-003 assumption. Source Essence row `DropChance=0` is not a modifier-choice weight. No uniform choice assumption or partial weight pool is introduced for these single targets.

Only item level at least the catalog's modifier level is supported. This deliberately retains the established conservative low-level boundary: effective character requirement (`reqlvl`) is not treated as proof that any item level may receive the Essence target. Existing family overlap, slots and unsupported rarity are blocked without changing the input item, stored film or unrelated omen. Unrelated omens are not consumed. Infinite remains blocked (WB-010).

The backend has an explicit reviewed action -> target map and validates its targets against the complete catalog. The client independently checks the expected target for the actual base, rejecting a valid Solar target substituted onto gloves. Lesser Body is Sanguine on gloves vs Healthy on Solar; ordinary/Greater Mind are Aqua/Opalescent on gloves vs Opalescent/Gentian on Solar. Rewriting an `amulet:` prefix would give incorrect results. Existing films keep their original per-frame rule and assumption evidence. New glove frames use `stocky-workbench-basic-essence-v18`; numeric ledger remains `stocky-unverified-numeric-assumptions-v11`.

## Follow-up priority and remaining blockers

1. Complete these 21 fixed results and their regression/film validation first, using the already complete ordinary glove catalog.
2. For Infinite, the gloves page lists Strength, Dexterity and Intelligence outcomes but their normal spawn tags differ. Strength applies via str_armour and Dexterity via gloves; Intelligence lacks a matching normal tag. It is not established whether Essence forces Intelligence onto this base or filters it. Neither a three-way result nor a two-way subset/1/N is guessed. WB-010 records the required evidence.
3. Inspect glove-specific Perfect/special Essences next, only after exact effect, identity/ranges, equipment applicability and every removal branch are proven. The basic gloves array alone does not establish that there are no special results. Shared-state actions such as Abyss/Breach/Hysteria cannot inherit Solar targets. Preserve the full pool and prove new dedicated targets before activation.
4. Catalyst quality, local Armour totals, sockets/runic/desecrated/instilled states remain under WB-004/WB-005. Current base Armour 15 is separately sourced; computed totals and quality scaling remain unsupported. No new formula or state is assumed to be game-verified.
5. WB-001/WB-003 stay unverified. Existing source-unit integer model and shared-ratio/HALF_UP assumptions are reversible user-authorised modelling choices, not promoted by this fixed-Essence extension.

Rollback: remove the explicit 21 glove overrides and matching registry/client support; retain original catalog and stored films/evidence. No DB schema, localStorage version/key, history tree, login or migration is introduced.
