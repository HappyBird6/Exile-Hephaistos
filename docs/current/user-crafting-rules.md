## 설계 해석과 아직 확정하지 않은 경계

다음은 대화 조사 요약 또는 구현 설계 해석이다. 사용자 직접 인용과 구분한다.

- Support와 자유 Workbench는 독립한다. 자동 제외 화폐를 수동에서도 금지하는 것으로 확대하지 않는다.
- 목표 지향 가지치기와 제작방법 edge(1~2개 화폐 조합), 단계별 높은 확률 안내와 탐색 완료 뒤 최종 경로 비교를 구분한다. 로컬 최고 확률이 전역 최적 경로라는 뜻은 아니다.
- 복구는 본 경로와 분리하고 실제 실패 결과를 입력받아 평가한다. 모든 가능한 외부 복구를 현재 엔진이 계산한다고 단정하지 않는다.
- first-hit의 엄밀한 수학 정의는 직접 사용자 원문이 확인되지 않았다. 최초 성공 후 흡수·중복 성공 합산 방지 등은 현재 계산 계약의 설계 해석이다.
- ‘최대 화폐 사용 횟수 없음’이나 탐색 완료 요구를 메모리·시간·상태 수 안전 제한을 모두 제거하라는 지시로 해석하지 않는다. 예산 초과는 미완료로 안내한다.
- R11은 S14에서 실제 explicit 속성 1개로 확정됐다. 표시 줄이나 목표 조건 MATCH 개수를 실제 옵션 수로 세지 않는다. 시작 준비 화폐는 같은 제작방법 안에서 처리하며, 후속 그래프 상태를 새 시작으로 자동 취급하지 않는다. 사용자가 수동으로 상태를 바꾼 뒤 명시적으로 새 탐색을 시작하는 R05는 별개다.
- 이미 확보한 목표는 현재 평가기에서 원래 상태의 MATCH 조건과 explicit 없는 상태의 조건을 비교해 판단한다. 복합 조건·OR/NOT의 모든 사용자 의도까지 정의하는 새 게임 규칙은 아니다. 품질만 바꾸는 선행 작업 뒤 카오스 허용 등 추가 예외는 이번에 도입하지 않았다.

## 목걸이 조건 판정 보완 — 2026-10-28

등록 목걸이 solar, stellar, amber, bloodstone, lunar, azure, crimson, pearlescent를 대상으로 전체 카탈로그를 검사한다. 기존 반지 43개 판정 완료를 목걸이 완료로 일반화했던 안내는 잘못이었다. 목걸이의 치명타·회생·방어·능력치 비율·주문 피해·스킬 레벨 및 특수 속성의 raw stat 매핑 17개가 누락되어 있었다.

이번 범위는 실제 아이템 속성의 조건 판정(evaluation)이며 별도 수치 확률 API(probability)의 지원 확대가 아니다. 신규 매핑은 evaluationOnly로 구분한다. 아이템의 원본 수치·가중치·게임 효과·화폐 자격은 바꾸지 않는다. implicit는 평가 자료에 남지만 새 목표 선택에서 제외하는 기존 R06을 유지한다. pseudo는 원래 정의된 기여분만 합산하며, 전역 방어도·회피·에너지 보호막 증가를 세 독립 옵션처럼 합산하지 않는다.

특수 속성 해석:

- 심연 군주의 표식: 원자료의 `essence_abyss_guaranteed_pick=1`은 표식 보유 표시다. 보유 시 1, 미보유는 ABSENT이며 0이 자동 MATCH되는 것으로 처리하지 않는다. 이 판정은 심연 제작·타락 결과를 구현했다는 뜻이 아니다.
- 최대 퀄리티 +20: `local_maximum_quality_+=20`은 추가 품질 상한이다. 현재 품질 20 또는 총 품질 상한 20이라는 의미가 아니다. 기폭제 적용 효과의 수치 투영은 별도 기존 제한을 따른다.
- 최대 Runic Ward 증가: `maximum_ward_+%`의 6~10을 증가율로 비교한다. 캐릭터의 최종 Ward 양을 계산하지 않는다.
- 재생은 원본 분당 값을 60으로 나눈 초당 값, 흡수율은 원본 permyriad를 100으로 나눈 %다. 기존 정확한 유리수 비교를 유지한다.

근거: 저장소 `catalog/solar-amulet/abyss-essence.catalog.json`, `breach-essence.catalog.json`, `runic-alloy.catalog.json` 및 각 목걸이 catalog의 stat 범위·표시문·출처 URL. [PoE2DB 목걸이 표](https://poe2db.tw/Amulets), [에센스 표](https://poe2db.tw/Essence)도 대조했다. 라이브 게임 전체 효과나 미검증 roll 분포까지 확정하는 근거로 사용하지 않는다.

기존 v5 판정 정의는 `definitions-v5-readonly.json`으로 바이트 보존한다. 그래프 v13 결과는 새 v14 판정으로 조용히 재개하지 않고 읽기 전용으로 열며, 새 탐색은 새 카탈로그를 사용한다. 저장 자료를 삭제·재작성하지 않는다.

### 에센스 목표 선택 누락 정정 — 2026-10-28

앞선 목걸이 전항목 지원 수는 조건 판정(evaluation) 수이며 실제 목표 선택 가능 여부까지 검증한 수가 아니었다. 사용자가 지적한 일반 방어도·회피·에너지 보호막 증가와 힘%·민첩%·지능%는 8종 모두 판정 SUPPORTED였지만, 일반 추첨 weight가 0이라는 이유로 eligible=false여서 UI의 추가 버튼이 비활성화됐다. 힘%는 이전부터 판정 정의에 있었으므로 17개 신규 판정 매핑 목록에 없었던 것이다.

이제 카탈로그에 실제 존재하는 완벽한 강화/무한 에센스의 생성 대상은 요구 아이템 레벨을 충족하면 목표로 선택할 수 있다. 일반 roll weight·에센스 생성 규칙·확률 모델·자동 사용 화폐 정책은 바꾸지 않는다. 다른 weight=0 옵션을 근거 없이 모두 선택 허용하지 않는다. 이 변경은 선택 자격 안내를 바로잡으며 기존 목표의 stat ID·단위·판정 의미·저장 형식은 유지한다.

- 일반 방어도·회피·에너지 보호막 증가는 `global_armour_evasion_energy_shield_+%`, 완벽한 강화 에센스의 단일 복합 속성이다. 원자료 범위는 20~30%이며 고정 30이 아니다. 목표 30 입력은 30%를 뜻한다. 세 별도 속성이나 0.30 비율로 변환하지 않는다.
- 힘/민첩/지능 증가는 각각 `strength_+%` / `dexterity_+%` / `intelligence_+%`, 완벽한 무한 에센스의 서로 다른 후보이며 범위는 각각 7~10%다. 네 속성 모두 원자료 요구 레벨은 72다. 낮은 레벨의 생성 제한과 기존 보유 수치 판정은 구분한다.
- 근거: `catalog/solar-amulet/perfect-enhancement.catalog.json`, `perfect-infinite.catalog.json`, 7종 목걸이 catalog, `crafting/workbench-definitions-v1.json` 및 `catalog/top-base-essences.json`의 실제 생성 대상 ID를 대조했다. 새 게임 데이터는 추정하지 않았다.
- 수정 전 8종 선택 자격 회귀 테스트가 모두 실패했고 수정 후 관련 백엔드 57개(아키텍처·카오스·6옵션·구형 저장 포함), 프런트 138개가 통과했다. 8종×4옵션×일치/상한초과/미보유의 격리 API 96건이 통과했다. 실제 격리 브라우저에서 한국어 검색→네 목표 추가→새로고침 복원을 확인했고, 방어 30% 목표의 미보유/20% NO_MATCH 및 30% MATCH를 확인했다. 전체 테스트 스위트를 재실행한 것은 아니다.
- lint/typecheck/format 및 Java 포맷·양쪽 빌드 통과. 초기 검사에서 예제의 옛 eligible 값, 신규 테스트 파일 문자셋 및 검증 컨테이너 환경 오류를 발견해 수정 후 재검증했다. 제품 UI 코드는 변경하지 않았고 프런트 빌드 227개 파일은 운영본과 동일하다.
- 서버 실행 JAR SHA256: `3004b4a56d90a43ff914a411195561900aadf8244a9f424dc8f1c041812571b8`. 배포 JAR의 모든 항목을 테스트 JAR와 바이트 비교했다. 저장 파일 23개(179,769,212 bytes)는 외부 백업 전체 복원 검증 후 적용하며, 운영 기록에 합성 평가 결과를 저장하지 않는다.

적용 후 확인: 9000/9001 health 정상, 사용자 저장 23개 파일의 크기·SHA256 전체 일치. DB·Redis·영구 볼륨·환경 파일 및 8080 서버를 보존했다.

## 심연 훼손·드러내기 제작 규칙 — 2026-10-29

출처: 이번 사용자 직접 지시. 아래는 확정된 앱 요구사항이며 현행 코드 구현 완료를 뜻하지 않는다. 게임 데이터의 후보 분포·징조 상세와 구분한다. 10/15의 심연 향후 사용 기록보다 최신이며, 필요한 심연 제작 경로를 설계 대상으로 포함한다. 과거 자동 제외 징조 전체를 일괄 허용하는 지시로 확대하지 않는다.

1. 훼손 후 드러내기 후보에는 기존 옵션과 심연 옵션이 포함된다. 드러내기는 화폐가 아닌 별도 행동이다. 후보 3가지를 실제로 본 뒤 사용자가 하나를 선택한다.
2. 메아리 징조는 현재 후보 3가지를 확인한 뒤 다시 굴려 새로운 후보 3가지를 보는 흐름이다. 이전 세 후보를 유지·복구·함께 선택할 수 있는지는 이번 지시로 확정되지 않았다. 항상 6개 중 선택하거나 독립 동일 추첨 3회라고 구현하지 않는다.
3. 훼손 슬롯은 드러내기로 옵션을 확정하지 않아도 실제 속성 1개다. explicit 슬롯과 접두/접미 수에 포함되고 제거 대상에도 포함되어야 한다. 아직 선택되지 않은 수치나 충돌군은 임의로 부여하지 않는다.
4. 아이템을 6옵션으로 채운 뒤에도 지정 징조를 이용해 훼손으로 얻은 옵션을 계속 재작업할 수 있어야 한다. 기존 훼손 슬롯을 재작업하는 것이며 일곱 번째 옵션을 추가하는 것으로 취급하지 않는다. 필요한 징조의 정확한 ID·소모 시점·부작용은 자료 확인 후 연결한다.

사용자가 설명한 세 전략을 별도 제작 후보로 보존한다. 항상 최적이거나 반드시 성공한다고 단정하지 않는다.

- **한쪽 슬롯 선완성:** 접두 또는 접미에 유효한 옵션 2개를 확보하고 훼손 슬롯으로 해당 쪽 3칸을 채운다. 이후 미완성 쪽을 작업한 뒤 훼손 슬롯을 원하는 옵션이 나올 때까지 재작업하거나 적당히 쓸 만한 후보로 확정한다. 한쪽이 꽉 찬 효과는 추가 후보의 슬롯 제한이며 모든 제거 화폐로부터의 면역을 뜻하지 않는다.
- **고가중치 비목표 옵션 임시 확보:** 남은 접두/접미를 훼손하고 드러내기 후보 중 가중치가 높은 비목표 옵션을 선택한다. 그 옵션이 실제로 차단하는 충돌군 때문에 이후 목표 후보의 확률이 높아지는 경우를 활용하고, 마지막에는 첫 전략처럼 쓸 옵션을 찾는다. 목표와 같은 충돌군을 막거나 목표 슬롯을 소진하면 오히려 불리할 수 있으므로 실제 후보 풀로 비교한다.
- **제거 위험을 나누는 더미:** 유효한 옵션이 있는 상태에서 제거 후 추가하는 에센스·합금 등을 써야 할 때, 훼손 슬롯을 더미 제거 대상으로 둬 유효 옵션을 잃을 위험을 줄이는 경로를 고려한다. 미공개 상태도 더미 슬롯으로 인정한다. 실제 제거 후보에 들어가는 경우에만 위험 감소를 계산하며 보호를 보장하지 않는다.

기존 카오스 첫 단계 정책은 유지한다. 심연 재작업은 별도 경로이며 옵션 감소·리롤을 이유로 첫 1옵션 카오스 단계로 돌아가지 않는다. 목표 판정 지원·목표 선택 자격·제작 전이 구현은 각각 따로 검증한다.

현재 구현과 누락, 데이터 확인 항목, 단계별 수정·검증 순서는 [심연 제작 구현 계획](../abyss-crafting-implementation-plan.md)에 기록한다. 이번 작업에서는 문서만 변경했고 제품 코드·서버는 변경하지 않았다.
