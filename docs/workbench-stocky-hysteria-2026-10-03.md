## Safety and probability boundary

Supports Rare items at catalog modifier level 45+ with at least one eligible unlocked explicit. No matching omen means all unlocked instances are candidates; one individually verified Crystallisation restricts that complete set to its side. For **every** candidate removal, the remaining item must allow the guaranteed target's family and suffix capacity. A failing branch blocks the complete operation, preserving input and omens. No candidate is silently filtered because its result would fail. A sole eligible instance in the same family may replace itself; a mixed set in which another removal would leave the conflicting family is blocked. A full suffix side may become valid with suffix-only removal, but prefix-only removal cannot free a suffix slot. A Fractured conflicting target remains blocked.

Both matching Crystallisation omens are prevented in the UI and rejected by the backend. No eligible unlocked instance on the restricted side, wrong rarity, insufficient level and unsupported condition preserve the input. One matching omen is consumed only on success; Blessed/Whittling/other unrelated omens remain. Failure and network error do not append history or consume activation.

Removal probabilities are the existing explicit `uniform-removal-v1` assumption, 1/N over the established eligible instance set; no published removal weights are claimed. Addition has one fixed target, probability 1, independent of its ordinary weight 500. The numeric source interval is verified; the five source integers are still the user-authorised WB-003 model, ID `assumed-source-integer-roll-v1`, not a game-verified probability or precision claim. Coupled models remain WB-001 conjectures and are untouched. New glove rule is `stocky-workbench-hysteria-v19`, ledger remains `stocky-unverified-numeric-assumptions-v11`.

The explicit backend replacement override is validated against known explicit definitions. It is used consistently for availability, action filtering and actual application. Client response validation checks the actual base-specific target, removal candidates/probability/evidence, matching omen accounting and every preserved/locked value. A Solar life-recoup suffix substituted into a glove Hysteria response is rejected even when structurally valid.
