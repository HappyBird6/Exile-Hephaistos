## 원인과 수정

합류 노드를 모든 비순환 선행 노드 뒤에 배치하고 incoming 작업에 출발/도착 상태 ID를 표시한다. 실제 전이·확률은 표시 배치 때문에 바꾸지 않는다. 순환 성분은 기존 깊이를 유지한다.

## 적용한 규칙

엑잘티드는 첫 변경 가능 속성을 추가해 카오스를 준비하거나, 합법적인 제거·추가 후속 작업의 더미를 추가할 때만 자동 탐색에 포함한다. 첫 일반 엑잘의 행운 성공 결과와 확률은 유지한다. 분열은 변경 가능한 속성 수에서 제외한다.

더미는 접두/접미 찬미 징조의 가능한 두 경우를 표시한다. 원래 속성·훼손 슬롯을 유지하면서 추가 더미를 소모하고 목표를 개선하는 실제 후속 분기가 있어야 한다. 더미 단계에서 우연히 목표에 도달해도 예정된 제거 작업을 생략하지 않는다. 일반 마무리 엑잘은 금지한다.

목표가 미완료여도 중간 상태·작업을 보존한다. 단독 희귀도 준비 단계는 중간 상태로 남기되, 여러 단계 준비 경로에 중복 희귀도 checkpoint를 생성하지 않는다. 이 구분은 저장복원에도 동일하게 적용한다. `RESOURCE_BUDGET`, 미확정 관측, 입증된 도달 불가를 같은 의미로 처리하지 않는다.

정책 v8 / kernel v10 / graph v17로 구분한다. 이전 v16 결과는 읽기 전용으로 보존하며 새 정책으로 조용히 재해석하지 않는다. 훼손 후보의 미지 추첨 확률은 만들지 않는다.

- 수정 중 전체: fixture 누락을 해결한 실행에서 959개 중 63개 실패. 기준과 공통 실패 40개, 추가 실패 23개. 이후 최종 영향 검사에서 추가 23개를 모두 재검증하여 통과했다(새 정책에 맞게 이름/계약을 바꾼 검사 포함).
- 최종 수정 후 전량을 다시 실행한 결과는 아니다. 전체 통과라고 주장하지 않는다. 비교 증거는 private staging의 `strict-failure-comparison.json`, XML 및 로그에 보존했다.
- 초기 전체 검사 72개 실패에는 fixture 누락 30개(직접 예외 29개 + 감싸진 예외 1개)가 섞여 있었다. 이 실행은 최종 회귀 판정에 사용하지 않았다.

남은 영향 범위 기존 실패:

1. `AutomaticRefinementsTest.changingChaosFailuresUseTheirOwnLawFor100Attempts`
2. `AutomaticRefinementsTest.routeStrategyUsesTheSameFinite100ChaosProbabilityWithoutAnUnlimitedRetryLoop`
3. `TerminalAdditionClassesTest.restoresBudgetPauseThenEnlargesWithoutChangingAnyOutcome`
4. `TerminalAdditionClassesTest.restoresRunningRepresentativeAndAliasesWithoutDuplicatingExecution`

확률 검사 입력 변경은 최초 자동 승인 검토에서 거절되어 실행하지 않았다. 사용자의 명시적 승인 후 확률 합계·흡수 분포·비용 assertions를 유지하고, 후반 엑잘 거부를 별도 검사로 추가했다. 상관분포·분열·6슬롯 수학 검사는 허용되는 접두/접미 더미 추가 단계에서 유지했다. 목표 완성에 마무리 엑잘을 쓰던 제품 검사는 새 정책에 따라 중간 상태·미완료·저장복원을 검증한다. 실패를 skip 처리하지 않았다.
